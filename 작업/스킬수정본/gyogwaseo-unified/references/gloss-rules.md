# 혼공해석지 각주 작성 규칙

차례: 형식·범위 → 실제 형태 → 묶는 범위 → 준동사·수동 → 숙어·전치사 → 관계사·접속사 → 조동사·완료·부정 → 대명사 → 검수.

각주는 학생이 문장을 스스로 읽는 데 필요한 의미 정보다. 대상과 기본 설명 수준은 `editorial-core.md`의 ‘목적과 범위’을 따른다.

이 기준은 혼공해석지에만 적용한다. 지문분석지·워크북·변형문제·미니 모의고사에는 단어·숙어·구문 각주를 제공하지 않는다. 그 자료에 남은 각주는 제목과 내용 모두 제거한다.

## 기본 형식과 순서

일반 단어:

    아래 용법별 기준의 영어 표제어 — 문맥상 한국어 뜻

표제어와 묶는 범위는 실제 용법에 따라 구별한다:

    일반 진행·-ing·비대상 to/조동사: 기능 공식 — 기능 뜻 / 원형 낱말 — 기본 뜻
    수동: be p.p. — ~되다 / produced — 생산된
    능동 완료: had p.p. — ~했다 / struggle — 애쓰다 (struggled는 struggle의 p.p.형)
    독립 p.p.: held — 개최된
    3인칭 단수 일반동사: helps → help — 돕다
    복수 명사: creatures — 생명체들 (복수형 유지)

- 문장 아래에 각주를 원문 등장 순서대로 배열한다. 아래 실제 형태·결합 기준으로 표제어를 선택하고, 여러 단어를 묶은 항목은 시작 위치를 기준으로 한다.
- 수동·능동 완료는 아래 용법별 기능/낱말 한 쌍을 제공한다. 실제 동사구의 완성 뜻을 통째로 각주에 추가하지 않는다. 결합하는 모습은 선정된 구조 힌트에서 지원한다. 고정 숙어와 완료진행의 별도 현행 기준을 모든 p.p.에 확대하지 않는다.
- 같은 표현이 다른 문장에 나오면 다시 제공한다. 한 문장 안의 중복 제거를 다음 문장의 각주 생략으로 확대하지 않는다.
- 고유명사는 예외로 각 지문의 첫 등장에만 제공한다. 상세 기준은 `proper-nouns.md`를 따른다.
- 전치사·접속사·준동사 등 기능어 뜻은 그 문맥의 한 뜻으로 정한다. `from — ~에서 (온)`처럼 고를 뜻을 괄호에 남기지 않고 `~에서`·`~에서 온`·`~에서 나온` 중 실제 의미를 택한다. 기능어에 `~하여, ~하면서`처럼 서로 다른 관계를 동시에 나열하지 않는다. 안내 표의 대안과 학생용 실제 각주를 구별하며, S′/A 공식의 조사 자리 표기 `(이/가)`와 다의어의 `(흔한 뜻: …)` 병기는 이 금지 대상이 아니다.
- 뜻은 해당 문장에 실제로 대입할 수 있어야 한다. 문맥 뜻이 흔한 뜻과 다르면 문맥 뜻을 먼저 적고 흔한 뜻을 뒤에 함께 제공한다. 예: `respect — 측면 (흔한 뜻: 존경)`. 두 뜻이 같으면 하나만 적는다. 실제로 존재하는 뜻만 사용하며 다른 문맥의 뜻을 목록으로 늘어놓지 않는다.

## 포함 범위

- 중1 수준부터 그 이상의 일반 단어를 모두 제공한다(U56). 해석에 필요한 일부만 선별하거나 ‘중1 수준 초과’로 범위를 좁히지 않는다. 필요한 숙어·구문도 제공한다. 기능 공식과 낱말은 아래 용법별 분리·결합 기준을 적용하고, 숙어·구문과 불필요하게 같은 정보를 중복하지 않는다.
- 기본 단어라도 문맥상 낯선 뜻, 불규칙 활용, 해석에 필요한 기능어, 지시 대상 확인이 필요한 대명사는 포함한다. ‘기본 단어’라는 이유만으로 필요한 정보를 빼지 않는다.
- 관계사·접속사, to부정사·-ing, 완료·수동·가주어 등 형태만으로 의미를 읽기 어려운 표현은 아래 방식으로 지원한다.
- 인명·지명·기관명·작품명 등 고유명사는 `proper-nouns.md`의 첫 등장 규칙으로 제공한다.
- and·but 및 you(대소문자 무관)의 단독 각주는 넣지 않는다. 원문과 S/V의 you나 필요한 숙어·구문 속 you는 지우지 않으며 다른 대명사까지 제외하지 않는다. 단독 you의 원문 위치는 lexical_coverage에 standalone-you 제외 근거로 남긴다. 문법 이름만 있는 항목, 본문과 무관한 사전 뜻도 넣지 않는다.

## 실제 형태와 활용형

- 3인칭 단수 **일반동사 각주 표제어**는 원형으로 제공한다. `helps → help — 돕다`, `studies → study — 연구하다`, `watches → watch — 지켜보다`처럼 실제 품사·용법·원형을 확인한다. 마지막 s를 기계적으로 삭제하지 않는다. 복수 명사 표제어는 `creatures — 생명체들`처럼 실제 복수형과 수의 의미를 유지하며, `species`·`news` 등의 s를 동사 어미로 추정하지 않는다. 단복수 동형·불가산·고유명사는 실제 용법을 따른다.
  - `provides A with B → provide A with B`처럼 묶인 동사 구문의 중심 동사만 원형으로 바꾸고 기존 숙어·전치사·A/B/V 틀·문맥 뜻은 보존한다. 어휘적 `has → have`·`does → do`는 해당 용법을 확인하며 이미 필요한 불규칙형 안내가 있으면 `(has는 have의 3인칭 단수형)`처럼 실제형과 원형을 연결한다. 보통의 규칙형마다 새 형태 설명을 붙이지 않는다. 기능을 나타내는 be·has·does나 `has p.p.`·`does not V` 등의 승인 공식은 이 규칙으로 바꾸지 않는다.
  - 바꾸는 것은 각주 표제어와 그 각주 ID를 재사용하는 구문 결합 연습의 도움말이다. 원문·청크·S/V·구조 힌트·인용·실제 연습 문제의 영어 활용형·뜻·수는 유지한다. 오늘의 낱말 등 별도 어휘 활동의 선정·표기는 바꾸지 않는다. 기존 -ed·-ing·수동/독립 p.p.·능동 완료 규칙에 s 기준을 확대하지 않는다.
  - 작성·수정한 해당 각주는 `verb_form.usage:third-person-singular`에 실제 한 단어 `source_span`, 검토한 `lemma`, `review_record`를 선언한다. 기계는 선언한 위치·철자 관계·표제어를 대조하며 명사/동사·어휘적 동사/조동사·정확한 원형을 자동 판정하지 않는다. 이 의미 검토는 담당 L 검수에서 확인한다.
- 수동·능동 완료는 기능 공식과 낱말을 나눈다. 수동의 낱말은 실제 p.p.형·수동 뜻(`be p.p. — ~되다 / produced — 생산된`), 능동 완료는 원형·기본 뜻과 실제 p.p. 관계(`have p.p. — ~했다 / find — 발견하다 (found는 find의 p.p.형)`)로 제공한다. 완료수동 `have been p.p.`는 수동이므로 실제 p.p.형을 유지한다. 전치사의 흔한 뜻으로 이해하기 어려운 `be provided with`·`be satisfied with` 등의 숙어는 한 각주로 유지한다. 독립 p.p.는 실제 형태·문맥 뜻(`held — 개최된`, `trained — 훈련받은`), 일반 정규과거 -ed는 원형·기본 뜻, 불규칙 과거는 현행 표기, 일반 -ing는 기존 기능/원형 분리를 유지한다. 이번 p.p. 구별 밖인 완료진행 `have been V-ing`와 오늘의 낱말 선정·표기는 별도 현행 규칙을 유지한다. 표제어 정규화는 원문·청크·S/V·실제 위치를 바꾸지 않는다. 일반 정규과거의 구문 표제어도 `tested A against B`가 아닌 `test A against B — A를 B와 비교하여 검증하다`로 쓴다. 능동 완료의 원형 각주에는 정규/불규칙 모두 실제 p.p. 관계를 반드시 짧게 알린다. 그 밖의 불규칙형 안내는 기존 기준을 따른다.
  - `fell — 빠졌다 (fall의 과거)`
  - `better — 더 나은 (good의 비교급)`
- 단어 뜻과 그 단어가 쓰인 구문 뜻을 중복하여 `allowing — 허용하다, ~하게 해 주다 (allow A to V — A(이/가) ~하게 해 주다)`로 쓰지 않는다. 이런 경우에는 `allow A to V — A(이/가) ~하게 해 주다`처럼 필요한 구문 하나만 표제어로 남긴다. 허락 문맥이면 ‘A가 ~하도록 허용하다’, 가능하게 하는 문맥이면 ‘A가 ~할 수 있게 해 주다’처럼 실제 문맥에 맞춘다. 원형 구문 표제어를 쓰더라도 원문 allowing과의 위치 연결은 보존한다. 구문 속 A·V에 들어간 낱말의 별도 뜻은 유지한다.
- `stop A from V-ing — A(이/가) ~하지 못하게 막다`처럼 V-ing의 연결 뜻을 구문에서 이미 제공했다면 같은 자리의 `V-ing — ~하는 것`을 다시 넣지 않는다. `reach — 도달하다`처럼 구문 안 낱말의 원형과 기본 뜻은 별도로 유지한다. 이 기준은 별도 `kind:function` 항목이 없는 경우에도 해당 구문이 활용의 기능을 이미 제공하면 적용한다. stop 자체를 꾸미는 `to V — ~할`이나 stop의 가능성을 나타내는 `can V`처럼 구문 바깥의 별도 기능까지 삭제하지 않는다.
- 구문 안에서 이미 제공한 같은 정보를 중복하지 않는다. `have been p.p.`·`be being p.p.`·`may have p.p.`는 각각 한 기능 공식이며 보조동사별로 다시 쪼개지 않는다. 그 공식과 p.p. 낱말의 용법별 각주 한 쌍은 필요한 학습 지원이므로 중복으로 삭제하지 않는다. 숙어 안의 기능과 숙어 바깥의 시제·양태를 구별한다.
- 정규과거의 원형이 분명하면 ‘과거형’ 분류를 덧붙이지 않는다. 같은 -ed라도 용법이 수동/독립 p.p.이면 실제형, 능동 완료 p.p.이면 원형+실제 p.p. 안내다. 철자만으로 일반 과거·p.p. 또는 수동·능동을 자동 판정하지 않는다.
- 한국어에서 발음 그대로 널리 쓰는 기초 단어는 자연스러운 외래어 표기를 사용할 수 있다. 문맥상 의미가 가장 분명한 표현을 선택하며 boat를 언제나 보트로 고정하거나 배를 금지하지 않는다(U52).

## 기능 공식·낱말의 분리·결합과 구문 예외

| 실제 용법 | 각주 예 | 구별할 점 |
|---|---|---|
| 일반 수동 | `be p.p. — ~되다 / produced — 생산된` | 낱말은 실제 p.p.형·수동 문맥 뜻 |
| 진행 수동 | `be being p.p. — ~되고 있다 / produced — 생산된` | be being p.p.는 한 기능 공식 |
| 능동 완료 | `have p.p. — ~했다 / find — 발견하다 (found는 find의 p.p.형)` | 원형+기본 뜻, 실제 p.p. 관계 필수 |
| 과거완료 | `had p.p. — ~했다 / struggle — 애쓰다 (struggled는 struggle의 p.p.형)` | ‘그때보다 앞서’를 각주에 덧붙이지 않음 |
| 완료 수동 | `have been p.p. — ~되었다 / recycled — 재활용된` | have가 있어도 수동이므로 실제 p.p. 유지 |
| 조동사 완료 | `may have p.p. — ~했을지도 모른다 / provide A with B — A에게 B를 제공하다 (provided는 provide의 p.p.형)` | 조동사 완료 공식과 동사 구문을 통째로 합치지 않음 |
| 독립 수식·보어 p.p. | `held — 개최된`, `trained — 훈련받은` | 별도 p.p. 기능 각주나 없는 be를 보충하지 않음 |

- 표의 뜻은 예시이며 문맥에 맞는 한 뜻을 고른다. 모든 현재완료를 ‘~했다’로 고정하지 않는다. 능동/수동·시간·부정·양태를 먼저 확인한다.
- `kind:function`·`kind:lexical`과 `combines_with`로 기능/낱말 한 쌍을 연결한다. 같은 원문 위치를 연결한 한 쌍은 허용하며 동점에서는 기능 공식을 먼저 제공한다. 원문 text·청크·S/V·spans·lexical_coverage는 실제 활용형 위치를 보존한다.
- 수동 낱말은 `produced — 생산된`처럼 실제 p.p.형, 능동 완료는 `find — 발견하다 (found는 find의 p.p.형)`처럼 원형이다. `find의 변화형`만 적거나 원형 자체를 ‘원형의 변화형’이라 부르지 않는다. 동사 구문도 `provide A with B`의 첫 동사와 본문 provided의 관계를 명시한다.
- `be p.p. — ~되다 / produced — 생산된`의 두 뜻을 기계적으로 더해 ‘생산된 되다’로 만들지 않는다. 구조 힌트로 선정되면 `produced(생산된) → is produced(생산된다) (be p.p.)`처럼 결합 후 문장 속 뜻을 보여 준다. 정확한 표시·우선순위는 `analysis-content.md`를 따른다.
- 일반 진행·동명사·현재분사와 분리 대상 부정사의 낱말은 기존 원형+기본 뜻을 유지한다: `be V-ing — ~하고 있다 / rise — 오르다`, `to V — ~하기 위해 / preserve — 보존하다`. 독립 p.p.에 `p.p. — ~된 / write — 쓰다`를 적용하지 않는다.
- 완료진행 `have been V-ing`는 이번 p.p. 낱말 구별의 대상이 아니다. 이전 승인대로 실제 동사구와 문맥 뜻을 한 각주로 유지한다. `have been p.p.` 완료수동과 혼동하지 않는다.
- 목적어·부사구를 계속 붙여 문장 전체를 한 각주로 만들지 않는다. `test A against B`처럼 구문 틀은 유지하고 A/B 자리에 실제 들어가는 낱말 뜻은 별도로 지원한다.
- 동사의 뜻을 완성하는 to V는 `decide to V — ~하기로 결심하다`, `struggle to V — ~하려고 애쓰다`처럼 묶는다. 같은 자리의 동사·to 기능을 중복하지 않고 V 자리에 실제 들어간 낱말 뜻은 별도로 제공한다. `had struggled to enter`는 `had p.p. — ~했다 / struggle to V — ~하려고 애쓰다 (struggled는 struggle의 p.p.형) / enter — 들어가다`로 나눈다.
- 별도 목적을 나타내는 to V는 분리한다: `use her money to buy books`에서 `use — 사용하다 / her — 그녀의 / money — 돈 / to V — ~하기 위해 / buy — 사다 / books — 책들`. 이를 `use A to V — A를 ~하는 데 사용하다`로 묶지 않는다.
- 단독 to V에 드문 뜻 `~하기로·~하려고·~하는 데`를 쓰지 않는다. 동사의 보충인지 별도 목적인지 실제 문맥이 불분명하면 예와 추천안을 하나씩 보고하고 사용자 답을 기다린다. 자연 해석까지 부자연스러운 직역으로 바꾸지 않는다.
- 명명 구문의 `be called A — A라고 불리다`, 출생 의미의 `be born — 태어나다`는 본문 was called/was born이어도 사전형 구문으로 유지한다. A의 낱말 뜻은 별도이며 모든 called/born을 같은 구문으로 자동 판정하지 않는다. 고정 숙어·상관어구·문맥상 가주어 It+that절은 각각의 기존 결합 기준을 유지한다.

수동 공식 바깥의 별도 기능은 지우지 않는다. `had to be changed`의 의무 `had to V`와 수동 `be p.p.`는 구별하고, `would be adopted`의 조동사와 수동도 실제 원문 위치로 각각 연결할 수 있다. 반면 `have been p.p.`와 `may have p.p.` 내부를 두 공식으로 다시 쪼개지는 않는다. ‘수동/완료 공식 한 개’는 같은 기능의 중복 분리를 막는 기준이지 다른 바깥 문법을 없애라는 뜻이 아니다.

## to부정사·-ing·분사·수동

아래 예시는 분리 대상과 결합 대상을 구별한다. `/`는 서로 다른 각주 항목의 경계이며 문장의 나머지 필요한 각주를 생략하라는 뜻이 아니다.

| 문장 속 표현과 문맥 | 각주 |
|---|---|
| They worked **to preserve** the forest. | `to V — ~하기 위해 / preserve — 보존하다` |
| **Reading** helps me relax. | `V-ing — ~하는 것 / read — 읽다` |
| The boy **standing** near the door is my brother. | `V-ing — ~하고 있는 / stand — 서다` |
| He greeted us, **waving** his hand. | `V-ing — ~하면서 / wave — 흔들다` |
| We used the **stored** food. | `stored — 저장된` |
| The letter **written** in French was short. | `written — 쓰인` |
| The storm **was predicted**. | `be p.p. — ~되다 / predicted — 예측된` |
| She **is reading** a book. | `be V-ing — ~하고 있다 / read — 읽다` |
| She hoped **to be invited**. | `hope to V — ~하기를 바라다 / be p.p. — ~받다 / invited — 초대받은` |

- to V는 문맥에 따라 ‘~하기’, ‘~할’, ‘~하기 위해’ 등 실제 기능 뜻을 사용한다. 모든 to부정사를 목적의 ‘~하기 위해’로 통일하지 않는다.
- 전치사 뒤 동명사도 기능 공식 `V-ing`와 원형 동사·기본 뜻을 독립 항목으로 제공한다. 구문 자체에서 이미 같은 V-ing 기능을 지원하면 기능을 중복하지 않고 원형 낱말은 유지한다.
- 현재분사 -ing의 기능과 원형 낱말은 기존 분리 기준을 유지한다. 과거분사 수식·보어는 `stored — 저장된`, `trained — 훈련받은`처럼 실제 형태와 문맥 뜻을 한 항목으로 제공하고 별도 p.p. 기능을 중복하지 않는다.
- 콤마 뒤 -ing도 포함하되 동시동작·이유·결과 등의 실제 관계를 확인한다. 콤마가 있다는 이유만으로 ‘~하면서’ 또는 분사구문으로 판정하지 않는다.
- 일반 수동태는 기능 공식과 실제 p.p. 낱말을 나누며, 고정 숙어의 결합 예외는 다음 절을 따른다. 동사에 맞는 피동·상태 뜻과 실제 시제·부정·양태는 힌트·해석에서 보존한다. 명사를 꾸미는 독립 p.p.에 원문에 없는 be를 추가하지 않는다.
- 불규칙 p.p.도 용법별로 구별한다. 독립 수식·수동은 `written — 쓰인`, 능동 완료는 `write — 쓰다 (written은 write의 p.p.형)`이다. 불규칙이라는 이유만으로 완료의 원형 관계 안내를 생략하지 않는다.

## 숙어·구문과 전치사

- **수량·종류+of 예외:** 수량·종류 표현 자체가 뒤 명사 앞에서 같은 어순의 한국어 `~의` 수식어로 대응하면 `metric tons of — (미터법) 톤의`, `some kind of — 어떤 종류의`처럼 of까지 한 각주로 묶고 표현 내부를 끊지 않는다. 해당 위치의 단독 of·중복 구성 낱말 각주는 제거하되 뒤 명사의 뜻은 별도로 둔다. 물리 단위인지 비유인지, 종류·수량 표현인지 일반 명사 후치수식인지는 실제 문맥으로 판정한다. `the amount of plastic — 플라스틱의 양`, `the destruction of nature — 자연의 파괴`처럼 어순이 뒤집히는 일반 명사구 전체에 이 예외를 적용하지 않는다. 이미 승인된 some of 등의 결합 표현은 기존 뜻으로 유지한다. `percent of — 퍼센트의`, `a significant number of — 상당한 수의`, `a certain species of — 특정 종의`도 실제 같은 어순·의미가 성립할 때 같은 방식으로 처리한다. 숫자나 뒤 대상 명사까지 각주 하나로 번역하지 않는다. `tons of`가 비유적 다량이면 물리 단위 뜻을 강제하지 않는다.

- 위 수량·종류+of의 승인 예외를 먼저 확인한다. 그 밖에는 전치사의 대표 뜻으로 해당 문맥을 이해할 수 있으면 단어와 전치사를 분리한다. 사전에 함께 등재되었다는 이유만으로 묶지 않는다.
  - `contribute — 기여하다 / to — ~에`
  - `respond — 반응하다 / to — ~에`
- 대표 뜻으로 해석되지 않는 결합은 필요한 구조를 묶어 제공한다.
  - `be provided with — ~을 제공받다`, `be satisfied with — ~에 만족하다`는 기능 공식·낱말·with로 억지 분해하지 않는다. 숙어 뜻만 다시 알려 주려는 독립 구조 힌트는 만들지 않는다. 실제 대상·동사·준동사 연결을 별도로 배우는 동사 구문 후보와 구별하며, 각주에 숙어로 묶었다는 사실만으로 후보라고 판정하지 않는다. `be provided with`처럼 각주에서 한 덩어리로 제공하는 표현도, 실제 원문의 A/B 대상 연결을 학생이 놓치기 쉬워 그 연결 자체를 배우는 경우에는 동사 구문 후순위 후보로 검토할 수 있다. 뜻을 한 번 더 외우게 하려는 힌트와 구별해 `explanation`에 실제 연결 대상·필요성을 기록한다. 이 조건을 모든 숙어의 자동 후보 허용으로 확대하지 않는다. 구문으로 해석하기·워크북의 적용 범위는 각 코너의 확정 기준을 따르고 같은 뜻을 반복 지원하려고 항목을 늘리지 않는다. `Books are produced in factories`처럼 in을 흔한 뜻으로 이해할 수 있으면 일반 수동/낱말/in 분리를 적용한다.
  - 본문이 `tested the samples against the standard`이면 `test A against B — A를 B와 비교하여 검증하다`로 제시하고 `samples`·`standard`의 뜻은 따로 제공한다. 기능 공식 설명이 필요 없는 일반 숙어에 같은 전체 뜻을 괄호로 반복하지 않는다.
  - `look for — ~을 찾다`
- be가 실제로 있는 고정 숙어는 be 원형과 패턴을 표제어로 사용한다.
  - 본문 `is about to begin` → `be about to V — 막 ~하려 하다`, 필요한 본동사 뜻은 `begin — 시작하다`로 별도 지원.
  - 본문 `were able to help` → `be able to V — ~할 수 있다`, 필요한 본동사 뜻은 `help — 돕다`로 별도 지원.
  - 본문의 실제 be 활용형과 표제어를 원문 위치로 연결하고, 이 표제어 정규화를 원문 영어 변경으로 확대하지 않는다.
  - be가 없는 분사·형용사 또는 become/get/seem 뒤에 be를 임의로 추가하지 않는다.
- be 없이 쓰인 분사에 be를 보충하지 않는다. 독립 p.p.와 형용사는 실제 형태·문맥 뜻을, 현재분사 -ing의 기능을 따로 제공한 낱말은 원형·기본 뜻을 쓴다.
- 대표 뜻이 아닌 시간 표현도 누락하지 않는다. `in 11 days`는 소요 기간이면 ‘11일 만에’, 현재를 기준으로 미래 시점이면 ‘11일 후에’로 묶어 제공한다. 두 뜻을 동시에 나열하지 않는다.
- `throw away`·`feed on`처럼 그 자체 뜻을 익히는 숙어는 각주로 제공하며 그것만으로 구조 힌트 후보가 되지 않는다. `provide A with B`·`help A V`·`allow A to V`처럼 뒤의 대상·동사·준동사를 연결해 해석하는 동사 구문만 후순위 후보로 삼는다. 전치사나 불변화사가 붙었다는 이유만으로 모든 구동사를 후보로 삼지 않는다. 상위 after·that 힌트에서 동사 뜻을 보존하는 `throw … away`·`feed on` 범위는 그대로 유지한다.
- 묶은 숙어의 전치사를 같은 범위에서 다시 제공하지 않고, 끊어읽기에서도 숙어를 가르지 않는다.
- 전치사 기본표와 경계 사례는 `preposition-meanings.md`를 따른다.

## 관계사·접속사

- 관계사·접속사는 뒤 구조와 문맥 뜻을 함께 적는다. 문법 명칭만 적지 않는다.
- 주격 관계사는 뒤에 부사가 끼더라도 `who V′`·`which V′`처럼 나타낸다. 뒤에 별도의 실제 주어가 있는 구조는 `that S′ V′`처럼 나타낸다.
- 관계사는 뒤 절이 앞말을 어떻게 꾸미는지 뜻으로 보여 준다.
- 전치사+관계대명사 각주는 `전치사 + 관계대명사 S′ V′ — S′(이/가) V′하는`으로 통일한다. 실제 문맥에서 이 틀을 적용하면 뜻·시제·관계가 손상되는 예는 강제로 고치지 않고 `reading_checks.review_record`에 원문·문장/각주 ID·적용 불가 이유·문맥상 뜻을 남겨 1차 L 독립 검수 때 사용자에게 보고한다. 일반 전치사·간접의문문·그 밖의 관계사에 이 통일 기준을 확대하지 않는다. 예: `by which S′ V′ — S′(이/가) V′하는 (관계대명사)`, `in which S′ V′ — S′(이/가) V′하는 (관계대명사)`. 선행사·전치사의 원래 관계는 내부 검토에 보존하고 실제 적용이 안 되는 구문에 없는 S′를 만들거나 시제·부정·양태를 지우지 않는다.
- 전치사+관계대명사는 위 통일 기준과 적용 불가 기록을 먼저 확인한다. 그 밖의 과거 관형 관계절은 실제 과거 연결을 보존해 `who V′ — V′했던 (관계대명사)`처럼 제공하고 힌트·연결 분석에도 `저질렀던`, `하고 싶어 했던` 등 맞는 관형 연결을 쓴다. 모든 관계절을 과거로 만들거나 계속적 which의 `그리고/그런데`를 `~했던`으로 바꾸지 않는다. 자연 해석은 문맥에 맞게 유지하며 연결 어미를 기계적으로 강제해 의미를 훼손하지 않는다.
  - `who V′ — V′하는 (관계대명사)`
  - `that S′ V′ — S′(이/가) V′하는 (관계대명사)`
  - `where S′ V′ — S′(이/가) V′하는 (앞말을 꾸미는 관계부사)`
- 관계부사 where가 받는 앞말은 실제 문맥으로 확인한다. places이면 장소, areas이면 분야·영역, situation이면 상황을 가리킬 수 있으므로 항상 물리적 장소라고 설명하지 않는다. 예: `three areas where changes are already happening`의 각주는 `where S′ V′ — S′(이/가) V′하는 (앞의 분야를 꾸미는 관계부사)`다. 뜻의 관형 연결과 구조 힌트의 실제 수식 대상이 일치해야 한다. 간접의문의 where는 이 틀과 구별한다.
- 쉼표 뒤 계속적 관계대명사 which는 표제어에 실제 콤마를 포함해 `, which V′`로 표시하며, 뜻 뒤의 `(계속적 관계대명사)` 라벨을 허용한다. 예: 추가 설명 문맥의 `, which V′ — 그리고 그것은 V′하다 (계속적 관계대명사)`. 이 V′ 단독 예시는 which 자체가 주어인 경우이며, 뒤에 별도의 실제 주어가 있으면 `, which S′ V′`처럼 그 S′를 보존하고 실제 역할에 맞게 해석한다. 제한적 관계절이나 다른 관계사에 콤마를 새로 붙이지 않는다. 앞말·앞 절에 설명을 더하거나 내용을 병렬로 이어 가면 ‘그리고’, 실제 대조·전환이면 ‘그런데’를 선택한다. which 자체를 but으로 간주하거나 뜻을 ‘그런데’로 고정하지 않는다. 실제 선행사와 수에 맞추고, 같은 구문의 구조 힌트·분석지 해석도 같은 연결 의미를 유지한다.
- 명사절 접속사는 뒤 절 전체가 들어가는 문맥 뜻을 적는다.
  - `that S′ V′ — S′(이/가) V′라고 (접속사)`
  - `that S′ V′ — S′(이/가) V′다는 (앞 명사의 내용을 설명)`
- when은 의문사·접속사 등 실제 기능을 구별한다.
- 관계사 항목에 뒤 동사구의 조동사 뜻까지 섞지 않는다. 그 동사구의 각주에서 제공한다.
- 각주의 `S′ V′`는 뒤 구조를 나타내는 틀이다. 실제 주어·동사를 적는 S/V 줄은 `analysis-content.md`의 콤마·절 구분 규칙을 따른다.

### 종속접속사와 의문사구의 구체적인 틀

실제 별도 주어·동사를 가진 종속접속사에는 `S′ V′` 틀을 사용한다. `because ~`처럼 뒤 구조가 사라지는 표제어를 만들지 않는다. 문법 이름표만 적지 않으며 부사절 접속사에는 불필요한 품사 라벨을 붙이지 않는다.

| 표제어 | 문맥에 맞춰 적용할 뜻 |
|---|---|
| because S′ V′ | S′(이/가) V′하기 때문에 |
| if S′ V′ | S′(이/가) V′하면 |
| when S′ V′ | S′(이/가) V′할 때 |
| although S′ V′ | 비록 S′(이/가) V′하지만; 실제 명사 서술이면 비록 S′(이/가) ~이지만 |
| unless S′ V′ | S′(이/가) V′하지 않는 한 |
| once S′ V′ | 일단 S′(이/가) V′하면 |
| while S′ V′ | 동시동작: S′(이/가) V′하는 동안 / 대조: S′는 V′이지만 |

위 표의 `/`·세미콜론과 보어별 뜻은 대안 설명이며 실제 각주에는 문맥에 맞는 하나를 선택한다. although는 `비록`을 생략하지 않고 실제 서술에 맞춰 어미를 활용한다. 예: 행동이면 `고군분투했지만`, 형용사이면 `어리지만`, 명사 서술이면 `학생이지만`이다. `하지만/이지만`을 학생용에 두 뜻처럼 함께 나열하지 않는다. be+명사·형용사 보어이면 한국어 서술에 맞게 ‘~이기 때문에·~라면·~일 때’ 등을 사용한다. 수동·진행에 쓰인 be를 상태 서술로 오판하지 않는다. 양보의 사실·가정 차이를 보존하고 although/even though/even if를 철자나 be 유무만으로 같은 뜻에 고정하지 않는다.

복합관계사도 실제 구조에 맞는 틀과 뜻을 적는다. 별도 주어가 있는 `whenever S′ V′ — S′(이/가) V′할 때마다`, `wherever S′ V′ — S′(이/가) V′하는 곳마다` 등이 해당한다. whoever/whatever/whichever 자체가 절의 주어인 경우 존재하지 않는 별도 S′를 가정하지 않는다. 주격 관계절의 S/V 표시 예외는 기존 V′ 단독 기준을 따른다.

간접의문문의 의문사구는 필요한 범위 전체를 표제어에 둔다. 별도 주어가 있는 경우 다음 틀을 사용한다.

| 표제어 | 뜻의 선택 기준 |
|---|---|
| how S′ V′ | 묻는 내용: 어떻게 S′(이/가) V′하는지 / 방법 자체: S′(이/가) V′하는 방법 |
| why S′ V′ | 왜 S′(이/가) V′하는지 |
| when S′ V′ | 언제 S′(이/가) V′하는지; 시간 부사절과 구별 |
| where S′ V′ | 어디서 S′(이/가) V′하는지; 실제 방향·장소에 맞춤 |
| whether/if S′ V′ | S′(이/가) V′하는지 아닌지 |
| how many/much N S′ V′ | 얼마나 많은 N을 S′(이/가) V′하는지 |
| what kind of N S′ V′ | 어떤 종류의 N을 S′(이/가) V′하는지 |
| what N S′ V′ | 무슨/어떤 N을 S′(이/가) V′하는지; 문맥에 맞는 하나 |
| whose N S′ V′ | 누구의 N을 S′(이/가) V′하는지 |

명사구의 한국어 조사는 실제 역할에 맞춘다. 위 목적어 예시의 ‘을’을 주어·보어·전치사 목적어에도 무조건 붙이지 않는다. 의문사구를 앞에 두어 영어 순서를 짚게 하되 `how 형용사/부사 S′ V′`는 `S′(이/가) 얼마나 ~한지/~하게 V′하는지`처럼 한국어 서술 관계를 보존한다. 예: how important it is → 그것이 얼마나 중요한지. 실제 동사 이름만으로 how의 뜻을 자동 선택하지 않는다.

의문사 자체가 주어인 간접의문문도 있으므로 ‘뒤에 별도 주어가 없으면 절이 아니다’라는 판별법을 쓰지 않는다. `what happened`는 절이다. 간접의문 what의 ‘무엇을/무엇이 ~하는지’와 관계대명사 what의 ‘~하는 것’을 문맥으로 구별한다. `how to V`·`what to V`·`where to V`는 별도 주어를 가진 위 유한절 틀에 넣지 않으며 각각 ‘~하는 방법·무엇을 ~할지·어디서 ~할지’ 등 실제 뜻으로 제공한다. 직접의문문 전체를 간접의문 틀로 표시하지 않는다.

`It is … that …`의 가주어/강조구문 판별은 that 뒤의 완전성 하나로 끝내지 않는다. 시간·장소를 강조해도 뒤에 주어·동사가 모두 나타날 수 있다. 강조 대상을 원래 자리에 되돌렸을 때의 문장·의미와 전체 문맥을 함께 확인한다. 문맥상 확인한 가주어 It+that절의 각주 통합은 [가주어 It의 연결 안내](#가주어-it의-연결-안내)를 따른다. It·that 철자만 맞는다고 강조구문을 가주어로 합치지 않는다.

문법 보완 근거: [Cambridge, cleft sentences](https://dictionary.cambridge.org/grammar/british-grammar/cleft-sentences-it-was-in-june-we-got-ma), [Cambridge, reported speech and indirect questions](https://dictionary.cambridge.org/uk/grammar/british-grammar/reported-speech-indirect-speech). 원본의 과도한 판별 공식을 교정하는 근거이며 새로운 교재 내용의 출처가 아니다.

## 조동사·완료·부정

- 기능 공식에는 실제 조동사·부정과 그 문맥 뜻을 넣는다. `can V — ~할 수 있다 / swim — 수영하다`, `could not V — ~할 수 없었다 / solve — 풀다`처럼 제공하며 could·might·would를 무조건 과거로 고정하지 않는다.
- `may have p.p.`는 하나의 공식이다. `may + have p.p.`로 다시 쪼개거나 `may have provided A with B` 전체를 한 각주로 합치지 않는다. 기능 공식과 `provide A with B`의 원형 구문·실제 p.p. 관계를 각각 제공한다.
- 능동 완료는 위 원형·p.p. 관계 기준, 완료수동은 실제 p.p. 기준을 적용한다. 완료진행의 별도 현행 결합은 유지한다. 현재완료의 결과·경험·계속 등 실제 문맥을 확인하며 한 뜻으로 고정하지 않는다.
- `had p.p. — ~했다`에는 ‘그때보다 앞서’라는 추가 풀이를 넣지 않는다. 힌트·분석에서 실제 문맥의 시간 관계를 훼손하지 않는다.
- 부정은 해당 기능의 실제 범위에 포함한다. 예: `have not p.p. — 아직 ~하지 않았다 / finish — 끝내다 (finished는 finish의 p.p.형)`, `not to V — ~하지 않도록 / wake — 깨우다`. 이미 제공한 같은 부정·조동사 정보를 중복하지 않는다.
- never·no처럼 그 자체로 부정 뜻이 있는 말은 별도 항목으로 둘 수 있다. 부분 부정과 전체 부정을 혼동하지 않는다.

## 대명사

- 구조 힌트의 `대명사[지칭 대상]`은 [별도 표시 규칙](analysis-content.md#대명사와-지칭-대상)이다. 이 변경으로 아래 각주의 기존 뜻·괄호 형식이나 단독 you 제외를 바꾸지 않는다. 각주의 지칭 내용은 힌트 참조 검수의 근거로 사용한다.
- you의 단독 각주는 사용자 지정으로 제외한다. 이 예외를 your·yours·yourself 등으로 자동 확대하지 않는다.
- they·their·them·themselves·our·us·his·hers·its는 문장마다 반드시 뜻과 실제 지시 대상을 괄호로 적는다. 예: `they — 그들은 (학생들)`. 뜻만 제공한 항목은 미완성이다. 이 목록 밖의 모든 대명사를 일괄 필수로 확대하지 않으며, 필요한 의미 지원은 제공한다.
- 대명사의 한국어 뜻은 원문 문장이나 제공한 구문 틀에 실제로 들어갈 조사와 함께 쓴다. 예: 주어 `we — 우리는`, `they — 그들은/그것들은`; 목적어 `us — 우리를`, 수여 대상 `us — 우리에게`. `allow A to V — A(이/가) ~하게 해 주다`의 A가 us이면 `us — 우리가`처럼 해당 한국어 틀에 맞춘다. 영어 목적격이라는 이유만으로 언제나 ‘우리를’로 고정하지 않는다. 소유격은 ‘우리의·그들의·그것의’처럼 소유 관계를 보존한다. 지정된 지시 대상 필수 목록과 you 단독 제외는 그대로 유지한다.
- 단독 주어로 쓰인 This·These도 `This — 이것은`, `These — 이것들은`처럼 역할을 보여 주되, `this protein`의 this처럼 명사를 꾸미는 한정사에는 조사를 붙이지 않는다.
- `in — ~안에 / it — 그것`처럼 별도 전치사 뜻이 이미 조사 역할을 제공하면 대명사에 같은 조사를 중복해서 붙이지 않는다.
- 지문 앞부분부터 읽어 지시 대상을 확정한다. 뜻만 기계적으로 적어 대상을 모호하게 남기지 않는다.

## 금지와 검수

문법 라벨의 허용·금지 범위는 `grammar-labels.md`를 따른다.

1. 원문을 왼쪽에서 오른쪽으로 읽으며 필요한 각주의 누락과 순서를 확인한다.
2. 각주의 뜻을 문장에 직접 대입하고 시제·수동·부정·양태와 대명사 지시 대상을 확인한다.
3. 수동/완료수동의 실제 p.p.·수동 뜻, 능동 완료의 원형·기본 뜻·실제 p.p. 관계, 독립 p.p.의 실제형·수식 뜻, 일반 정규과거 원형, 불규칙 과거 현행, 일반 -ing 분리를 구별했는지 확인한다. 숙어 예외와 완료진행 현행 규칙, 동사 보충 to V 결합/목적 to V 분리 및 단독 ~하기로·~하려고·~하는 데 오류도 확인한다. 같은 철자의 -ed를 과거/과거분사로 자동 판단하지 않는다. 원문·S/V·힌트의 실제 활용형과 원문 위치를 보존하고 기능·낱말 중복 및 자기참조 주석을 제거한다.
4. 다른 문장의 반복 표현에 각주가 있고, 고유명사만 지문별 첫 등장 예외를 따르는지 확인한다.
5. 숙어가 끊어읽기에서 갈라지지 않았는지, 관계사에 조동사 뜻이 섞이지 않았는지 확인한다.
6. 각주의 뜻과 같은 문장의 끊어읽기 해석·구조 힌트·분석 내용이 일치하는지 확인한다. 같은 구문은 기능 각주의 조사·연결 어미가 구조 힌트의 해당 부분에 그대로 대응하도록 맞춘다. 예: 각주 `with + A + V-ing — A(이/가) ~하면서` ↔ 힌트 `[지구가 더 따뜻해지면서]`. 다른 문맥의 with 구문까지 `~하면서`로 고정하지 않고 실제 의미에 맞춘다.
7. 해석지 외 자료에 단어·숙어·구문 각주가 남지 않았는지 확인한다.
8. 기능어는 해당 문맥의 한 뜻인지 확인한다. 예: `By — ~무렵에는`에 선택하지 않은 `~까지`를 쉼표로 남기지 않는다. `(이/가)` 공식 슬롯·흔한 뜻 안내·실제로 허용된 일반 낱말 뜻 병기를 이 검사로 삭제하지 않는다.

## 공식 슬롯 표기

목적어 자리는 `A`, 두 항목은 `A`·`B`로 표시한다. 예: `with + A + V-ing — A(이/가) ~하면서`. 뜻은 해당 문맥의 구조 힌트와 같은 연결 표현으로 맞추며, `with + 대상 + V-ing`·`with + 목적어 + V-ing`를 출력하지 않는다. 실제 인용 구절과 일반 한국어 설명은 보존한다.


## 가주어 It의 연결 안내

- 문맥상 가주어 It+that 진주어로 확인한 구문은 전체 틀을 한 각주로 제공한다. 예: `It seems that S′ V′ — S′(이/가) V′하는 것 같다`, `It appears that S′ V′ — S′(이/가) V′하는 것으로 보인다`, `It is likely that S′ V′ — S′(이/가) V′할 가능성이 높다`. 예시에 없는 동사·형용사도 같은 실제 구조이면 적용한다. 같은 위치의 It과 that을 각각 독립 각주로 다시 적지 않는다. that절 내부의 필요한 낱말·기능 각주는 계속 제공한다.
- 위 구문은 본문에서도 **It부터 that까지 끊지 않는다.** that절 내부의 후치수식 등 필요한 경계는 유지한다. 예: `It seems that the people / in the room / are ready.`를 허용하며, 문장 전체를 무조건 한 청크로 합치지 않는다.
- 이 예외를 가주어가 아닌 지시 it·가목적어·강조구문에 적용하지 않는다. to 진주어 등 다른 가주어 구조는 실제 진주어 연결을 짧게 안내한다. 예를 들어 to부정사가 실제 진주어이면 뒤의 to부정사라고 안내하고 `It is important / to study hard.`의 기존 경계는 유지한다.

## 각주 ★와 항목 구분

상관어구는 멀리 떨어져 있어도 A·B를 포함한 하나의 틀로 설명한다. `not only A but also B — A뿐 아니라 B도`, `either A or B — A 또는 B 중 하나`처럼 실제 관계에 맞는 뜻을 제공하고 A·B 안의 필요한 낱말 뜻은 따로 지원한다. 상관어구 사이의 긴 구간을 끊어읽기에서도 하나의 청크로 강제하지 않는다.

오늘의 낱말 선정에는 해석의 핵심성·다의어 함정을 우선 고려한다. ★ 표시는 확정된 그 학습 단위의 오늘의 낱말 목록에 연결한다. 같은 단위의 다른 문장에 반복 등장해도 대응 항목에 ★를 표시하며 문장별 절반 상한은 두지 않는다. 구가 여러 각주 항목에 나뉘면 첫 구성 항목에 표시하고, 별표를 위해 뜻을 합치거나 바꾸지 않는다. 각주 ★는 남색 굵게 8.5pt이며 핵심 문장 주황색 ★와 별개다.

표제어·뜻·원문 위치·기능/낱말 종류·결합 대상 ID·원형 관계·흔한 뜻·별표 대응 어휘 ID는 구조화한 별도 값으로 보존한다. 화면의 ` / `나 `—`를 단순 분할하여 데이터를 역추정하지 않는다. 항목 구분자 ` / `를 괄호 안에 넣지 않는다. 수동·능동 완료는 승인된 기능/낱말 분리를, 숙어·완료진행과 나머지는 해당 결합/분리 기준을 보존한다. 능동 완료의 실제 p.p. 관계 안내는 허용된 필수 괄호이며 중복 풀이로 삭제하지 않는다.

불규칙형의 원형 관계는 학생이 알아볼 수 있게 설명한다. `founded`가 일반 정규과거이면 `found — 설립하다`, 독립 p.p.이면 `founded — 설립된`처럼 용법을 구별하고 find의 과거 found로 오해하지 않게 한다. 같은 위치의 변화형과 원형을 별도 중복 항목으로 늘어놓지 않는다. 완곡·가정의 could·might·would에 기계적으로 ‘~의 과거’를 붙이지 않는다.

S/V와 각주의 범위는 구별한다(U57). `She is able to swim.`의 V는 is만 표시하지만 각주의 `be able to V — ~할 수 있다`는 유지한다. 각주를 묶었다는 이유로 able과 to swim을 동사 칸에 포함하지 않는다.
