# 요청 시 만드는 블로그·카페·썸네일

교재 기본 생성과 분리된 선택 작업이다(U24). 사용자 요청이 있을 때 작성하며 게시·발송은 별도 지시가 있어야 한다. 새 교재마다 자동으로 광고 페이지를 덧붙이지 않는다.

## 공통 내용

현재 검증한 교재의 과목·출판사·저자·과·범위·문장 수·각주 수·파일 상태를 사용한다. 학습 단위 수와 원문 단락 수를 혼동하지 않는다. 내신 등급과 모의고사 등급을 구별한다. 앞선 교재의 수치·학년·파일 이름·광고 문구를 새 교재의 사실로 복사하지 않는다.

학습 순서는 끊어읽기 → S/V 확인 → 나의 해석 작성 → 지문 분석지의 영어·한국어 끊어읽기와 자연 해석 비교로 설명한다. 폐지된 별도 모범 해석·단어장·수업용 모드가 수록된 것처럼 소개하지 않는다. 원고가 QC 상태이면 독립 검수 완료·출고 완료로 소개하지 않는다.

다운로드·블로그·카페 링크는 실제 확인된 주소를 사용한다. 미정 주소는 작성용 초안에서 미정이라고 표시하고 게시 가능한 완성 링크처럼 쓰지 않는다. 실제로 게시하지 않았으면 ‘블로그에 올렸습니다’라고 적지 않는다. 다음 과 업로드 같은 예정은 사용자가 정한 계획이 있을 때만 적는다.

원본 C의 컨업 500단어·36일·118회 재등장·무료 DAY 1~3·DAY 4~6 신청·강의 경력·시험 전 완주 등의 광고 문구는 특정 상품의 과거 정보다. 요청 시 현재 상품 원고·승인된 안내·실제 링크로 확인해 사용한다. 교과서 스킬 통합만으로 그 문구가 모든 교재에 승인된 것은 아니다. QR이 들어가면 실제 목적지와 안내 링크가 일치하는지 확인한다.

## 글 구성

- 블로그: 교재 식별 제목, 인사와 자료 소개, 실제 수록 범위·수량, 학습법, 앞부분 미리보기, 전체 자료 위치, 요청한 경우 확인된 관련 상품 안내.
- 카페: 간결한 소개와 학습법·실제 블로그 링크. 두 카페용을 요청하면 황영카·기출비 두 글의 제목과 문장을 각각 작성하되 내용·수치·대상·링크를 일치시킨다. 서로 다른 문구가 검색 노출을 보장한다고 주장하지 않는다.
- 네이버 붙여넣기 원고는 순수 텍스트로 만들며 Markdown 링크·이모지를 자동 넣지 않는다. 기존 기호 ▶·▷···→·구분선을 활용한다. 실제 파일명은 현재 교재명과 요청 종류로 식별한다.

블로그 미리보기는 기본 앞 3문장이다. 사용자가 범위를 지정하면 따른다. 영어 청크·S/V·각주는 검증한 원고에서 파생하고 별도로 재작성하지 않는다. 첫 문장의 해석 예시는 분석지의 확정 자연 해석으로 제공하고 ‘분석지 해석 예시’라고 표시한다. 미리보기 각주는 앞에서 최대 5개를 원문 순서로 보여 주며, 일부만 제시했다면 생략 표시와 전체 수록 안내를 둔다. 미리보기 제한을 교재 본문의 각주 생략 규칙으로 확대하지 않는다.

## 썸네일 — 원본 보존(U59)과 승인 예외(U63·U64)

사용자의 “썸네일은 건드리지마. 클로드가 만든 그대로를 쓸거야”라는 원본 보존 지시(U59)를 기본으로 한다. 이후 승인한 예외는 별도 입력 변환 도구(U63)와 하단 ‘모범 해석 수록’을 ‘분석지 해석 수록’으로 바꾸는 한 곳 정정(U64)뿐이다. 나머지 코드·문구·디자인·배치·글꼴·각주 선택·잘림 처리·로고는 보존한다. 교재와 홍보 TXT의 내용 수정 규칙을 추가 썸네일 개작 권한으로 확대하지 않는다.

`scripts/build_thumbnail.py`는 원본의 해당 문구 바이트만 교체했다. 수정본 SHA-256은 `551582631d84b76e3aaeaa38fb7491c18980be9fe2b66f44660a80c86c735ec0`이며, 문구를 되돌리면 원본 해시 `c7c2436ee53bd725913193a0ad07fcb7421e51c0892ba31074f36472c695ca40`과 일치한다. 로고는 바이트 그대로이며 SHA-256은 `3ef55a70160bf49a178b984cb1813a01af4581dd07c72618034d63e303d61360`이다. 생성기는 기존 클로드 입력의 title 및 sections[].sentences[].chunks/gloss 등을 읽고, 원래 Linux NotoSansCJK TTC 경로와 한국어 인덱스 1을 유지한다. 공통 원고는 아래 별도 도구로 입력만 변환한다. 환경 차이를 이유로 글꼴·경로·그리기 코드를 바꾸지 않는다. 기존 이미지는 그대로 보존하며 문구 정정이 필요하면 승인된 생성기로 새 출력 경로에 생성한다. 입력·문구 검증을 실제 PNG 렌더·시각 검수 완료로 보고하지 않는다.

수정하려고 만들었던 새 썸네일 코드·추가 Noto Sans KR 글꼴·시험 이미지는 통합 배포 대상에서 제외했다. 클로드 원본 썸네일을 공통 조판 새 구현의 검증 결과로 보고하지 않는다.

### 통합 원고의 썸네일 입력 변환(U63)

사용자가 승인한 별도 `scripts/convert_thumbnail_input.py`로 공통 원고를 기존 클로드 입력 형식으로 변환한다. 이 추가 도구는 원본 썸네일 생성기·문구·디자인·미리보기 선택 규칙을 변경하지 않는다. 통합 원고를 `build_thumbnail.py`에 직접 넣지 않는다.

```text
python scripts/convert_thumbnail_input.py manuscript.json 교재_썸네일입력.json
python scripts/build_thumbnail.py 교재_썸네일입력.json 교재_썸네일.png
```

변환기는 공통 학습 원고 구조 검사 후 원문 순서로 모든 문장의 영어 청크와 각주를 옮긴다. 각주의 표제어·문맥 뜻·지시 대상·★ 여부와 순서를 유지하고, 미리보기 선택·각주 표시 수 제한은 원본 생성기에 맡긴다. 과목·출판사/저자·과는 metadata에서 가져오며 UNIT04·LESSON04·제4과 등 숫자로 식별되는 과 표기는 썸네일 입력에서만 4과로 맞춘다. 공통 원고·기존 교재 파일명은 바꾸지 않는다. 원본 제목 분석기로 정확하게 구분할 수 없는 표기, 원문 누락·변경, 미확정 학습 단위는 오류로 중단한다. 빈 썸네일 입력으로 조용히 통과시키지 않으며 기존 출력 JSON도 덮어쓰지 않는다.

입력 변환에는 Pillow·글꼴이 필요 없다. 실제 PNG 생성 전 `python -m pip install -r requirements-visual.txt`로 Pillow 등 선택 의존성을 설치하고, 원본이 지정한 NotoSansCJK TTC 글꼴도 확인한다. 글꼴 파일은 이 의존성 명령으로 설치되지 않는다. 입력 변환 시험 통과는 PNG 생성·시각 검수 완료를 뜻하지 않는다. 변환 입력은 썸네일 전용 파생 자료이며 다른 구형 교재 생성기의 전체 입력으로 사용하지 않는다.

## 요청한 홍보 TXT 실행

```text
python scripts/build_promotion.py manuscript.json --blog 교재_블로그.txt --cafe1 교재_황영카.txt --cafe2 교재_기출비.txt
```

요청한 출력 옵션만 지정한다. 기존 TXT는 실제 파일을 읽고 해당 부분을 수정하며 생성기로 덮어쓰지 않는다. 이 도구는 게시하지 않는다.

선택 입력 promotion에는 target_label, preview_count(기본 3), review_record(실제 검수 증거 위치), links를 넣는다. links의 blog/download/collection은 각각 `{ "url": "실제 주소", "verification_record": "확인 근거" }`이다. 없는 링크는 미정으로, 없는 독립 검수 증거는 확인 필요로 표시한다. 기록 입력이 검수 자동 인증은 아니다. related_product는 현재 승인된 verified_copy와 verification_record가 있을 때만 추가한다.
