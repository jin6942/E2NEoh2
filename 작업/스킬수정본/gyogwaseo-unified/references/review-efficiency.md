# 검수 품질을 유지하는 입력·기록 절약

이 절은 사용자가 위임한 검수 운영 개선이다. 내용·표기·각주·구조 힌트·문항 편성·서식·MASTER 기준은 바꾸지 않는다. 기존 S·L·M·N·J·K·R 책임과 문항의 독립 2인 블라인드 풀이, 전체 실제 저장본 대조를 유지한다. 경고를 줄이려고 원문·힌트·선지·정답·글꼴을 자동 수정하지 않는다. 새로운 교육 기준이 필요하면 실제 예와 영향·추천안을 사용자에게 먼저 제시한다.

## 제작자가 먼저 정리할 것

S 원문 검수 전에 원문 전사, 공백, 실제 문장·단락 경계와 공통 단위 구성을 끝낸다. S PASS 뒤에는 해당 버전을 기준으로 제작한다. 오류가 발견되면 원문을 고칠 수 있으나 변경을 숨기지 않고 S 재검과 영향받는 해석·분석·문항 검수를 연결한다. 영향이 불명확하면 해당 단계 전체를 재검한다. 최초 S를 생략하거나 틀린 원문을 고정하지 않는다.

`review_preflight.py`는 기존 `check_book` 결과와 제작자용 진단을 짧게 모은다. 기존 검사에 있는 순서 선지·밑줄·공유 장문·기존 답 분포·단위별 수량·원문 복원 검사를 또 다른 기준으로 중복 구현하지 않는다. 기존 오류나 원문 확인 대기를 무시하지 않는다.

워크북·문제부 작성 전에는 `review_preflight.py 원고.json 학습진단.json --scope learning`으로 학습부만 진단한다. 해당 보고서의 `scope=learning`·`NOT_CERTIFIED`는 완성책 검증이나 출고 승인으로 사용할 수 없다. 완성 원고에는 기본 `--scope full`을 사용한다.

추가 진단의 확정값은 다음과 같다. 모두 **학생용 내용의 새 작성 규칙이 아니다.**

| 진단 | 처리 |
|---|---|
| 쉬운 풀이 문장 구분 후보 | 선정 원문 수 3개와 비어 있지 않은 설명 목록 검사는 유지. 설명문 총수의 상한·2문장 하한은 없으며 총수만으로 경고하지 않는다. 한 배열 원소에 여러 문장인 후보만 경고하고, 인용·약어·한 문장 한 내용과 연결·문체는 L이 [쉬운 풀이 기준](analysis-content.md#각-문장-쉬운-풀이)으로 확인 |
| 길게 노출된 힌트 | 원문 15단어 이상에서 **실제 표시 영어**가 원문 단어 수의 80% 이상이면 경고. 내부 span 전체를 노출이라고 간주하지 않음. 짧은 문장·기능 공식형은 일괄 탈락시키지 않음 |
| 선지와 지문의 일치 | 정답만이 아니라 다섯 선지 모두 연속 5단어 이상 일치하면 위치를 경고. 원어 사용을 금지하거나 유의어로 자동 치환하지 않음 |
| 요약문 A/B | 출력 요약문 안에 A 다음 B가 각각 한 번 나타나는지 확인. 원문의 근거 등장 순서를 강제하지 않음. 두 자리의 의미와 선지 대응은 M/N이 판단 |
| 무관 문장 표적 간격 | 비연속 표적은 재확인 경고. 기존 문항 복원·표시 규칙 유지 |
| 회차별 정답 분포 | 정보로 제공. ①~⑤ 각 1회라는 새 규칙을 만들지 않음 |

명사+to/with, 전치사 뜻, 관계사/접속사 힌트의 누락·최소 표시 범위, 직역과 영한 문법 강조의 실제 대응, 유반 타당성은 기존 내용 지침대로 문맥을 읽어 검수한다. emphasis_links의 위치 통과만으로 의미 대응을 승인하지 않는다. 공식 S′/A 주어 조사와 문법 고정어+ing의 누락, 문맥 기능어 뜻 전체의 대응, 명시적 동사 결합 정책의 정확한 분류·영어 무강조·한국어 공식 뜻을 확인한다. 일률적 문자열 결합·분리로 대체하지 않는다. 수동/완료수동의 실제 p.p.·수동 뜻과 기능 분리, 능동 완료의 원형·기본 뜻·실제 p.p. 관계, 숙어·완료진행 예외, 독립 p.p. 실제형, 일반 정규과거 원형, 일반 -ing 분리를 실제 용법으로 확인한다. 생략 that의 접속사·관계사 구분과 양쪽 연결, 기능어의 쉼표로 나열된 불필요한 대안도 확인한다. 동사 보충 to V는 구문으로 묶고 목적 to V는 분리했는지 확인한다. 단독 to V의 ~하기로·~하려고·~하는 데는 오류로 확인한다. lexical_step의 낱말 뜻→결합 뜻과 동사 목적어 제외, 독립 p.p.의 held↔개최된 전체 대응도 직접 읽는다. 이 예외를 by/without V-ing에 확대하지 않는다. verb_form/verb_phrase/verb_construction 선언 수만으로 용법·의미 검토를 대신하지 않는다. 경고 0개도 내용 합격을 뜻하지 않는다.

## 작은 입력과 독립성

사용자 눈검수 후 [추가 요청 검수](user-feedback.md)는 현재 유효 요청·조건을 담당 범위와 함께 전달한다. 사용자 원장·수정 이유·전후 대조는 정답을 드러낼 수 있으므로 questions-blind에 넣지 않고 M/N의 답·근거 저장 뒤 비교 단계에만 제공한다. 실제 변경이 없어도 요청 조건을 확인하므로 changed-only의 빈 결과는 완료가 아니다. 원장 해시는 별도 요청 게이트에 연결하며 기록 추가만으로 모든 단계의 과거 지문을 바꾸거나 전면 재검하지 않는다.

전체 원고가 권위 데이터이고 부분 검수 자료는 보조 입력이다. `review_packets.py` 또는 `export_handoff.py --review-packet`으로 생성한다. 생성기는 전체 기계 입력을 검사하고, 이전 원고와 현재 원고를 모든 필드에서 비교하여 영향 범위를 넓힌다. 수동 변경 목록만 믿지 않는다.

- `learning`: 전체 공통 학습 단위를 소유 범위로 준다. 각 문장·각주·힌트·해석·분석과 필요한 원문/이웃 문맥을 함께 준다. 문장 수 때문에 소제목 단위 안을 자르지 않는다. 문맥으로 첨부한 단위는 검수 완료 범위에 포함하지 않는다.
- `questions-blind`: 현재 학생에게 보이는 발문·실제 변형 지문·밑줄·선지만 준다. 공유 장문은 연결 문항 모두 포함한다. 정답·해설·이전 정답·변경 이유·정상형 복원·원문 순서·교사용 해석 원고를 먼저 주지 않는다. 학습 원고/비교 자료를 이미 본 에이전트는 새 블라인드 검수자로 사용하지 않는다.
- `questions-compare`: 블라인드 답·근거를 실제로 저장한 뒤 별도 대조 단계에 준다. 정답·번역·근거·변경 내용을 확인한다. 그 단계에서 답을 복사하여 최초 풀이로 기록하지 않는다.

대조 패킷의 `comparison.length_reviews`는 담당 문항별 원고 `length_review`와 계산된 `length_comparison`을 함께 제공한다. 이 제작자 근거는 블라인드 패킷에 포함하지 않는다. 교사용 문제 QC TXT의 같은 진단은 `export_handoff.py --qc-diagnostics`로 명시적으로 요청한다. 진단 QC를 이름만 바꿔 FINAL로 사용하지 않고 FINAL은 해당 옵션 없이 다시 내보낸다.

이전 원고를 지정한 `--changed-only`는 영향 단위와 연결/공유 문항까지 포함한다. 원문·메타데이터·단위 재편성·알 수 없는 변경은 해당 단계 전체로 되돌린다. 지정한 ID로 계산된 영향 범위를 줄일 수 없다. 변경 0건은 ‘부분 자료에 할당 0건’이며 검수 PASS가 아니다. 전체 FINAL TXT를 부분 자료로 덮어쓰지 못하며 기존 전체 내보내기 형식은 유지한다.

새 실행에는 담당 원고, 기존 필수 공통·담당 지침, 실제 버전/해시와 필요한 근거만 준다. 긴 이전 대화·과거 전체 로그·전 회차 이미지·동일 원고 덤프를 반복 첨부하지 않는다. 참조 파일 목록/해시는 최신 지침을 찾는 수단이지 지침을 읽었다는 증거가 아니다. 필수 규칙을 제목만 보고 생략하지 않는다.

## L·J/K 배정과 전체 연결

L은 약 12~13문장을 작업량 참고치로만 삼고 실제 공통 학습 단위 경계에서 나눈다. 긴 단위는 분할하지 말고 그대로 맡긴다. 각 단위에는 원문 전체·필요한 앞뒤 문맥을 제공하고 별도 실제 L 연결 검수자가 전 단위의 용어·지시 대상·글의 흐름·교차 참조를 확인한다. 전체 연결은 프로그램 집계나 이름만 있는 총괄 승인으로 대체하지 않는다.

J/K는 약 10쪽씩을 참고치로 새 실행에 배정한다. 전 페이지를 확인하고, 작은 각주·밀집 표·문항·해설·수정 쪽은 글자를 판독할 수 있는 실제 해상도로 본다. 이미지 scale 상한을 두지 않는다. 묶음 경계의 앞뒤 페이지를 한 담당자에게 함께 제공하여 제목 고립·문제/선지 분리·계속 표기·큰 빈 공간을 확인한다. 모든 인접 페이지 연결에 실제 담당자를 둔다. 정상 페이지 이미지를 매 도구 호출마다 다시 출력하지 않는다.

최종 출고의 전체통합본+분권 5개는 [분권 출고](split-delivery.md)를 적용한다. 통합본과 분권을 각각 실제 Word로 확인하며 한 권의 통과를 다른 권의 조판 통과로 복사하지 않는다. 내용이 그대로 추출됐으면 의미 검수는 현재 원본의 근거와 보존 검사를 연결하고, J/K는 바뀐 문서별 페이지 흐름을 확인한다. 각 권 안의 인접 페이지를 검수하며 서로 다른 권의 끝/시작을 한 문서의 인접 쪽으로 취급하지 않는다. 내부 PDF는 허용하며 사용자에게 기본 전달하지 않는다.

오류 없는 S/source 전체 검수는 `"findings": []` 또는 명시적인 `"no_findings": true` 중 하나로 발견 사항 없음을 선언한다. 두 필드 모두 없으면 미기록이며 통과하지 않는다. findings가 있으면 반드시 배열이어야 하며, `no_findings:true`와 비어 있지 않은 findings를 함께 적지 않는다. 발견·수정·재검증 사항은 기존 findings에 그대로 남긴다. 다른 종류와 분할 자식 기록에는 기존 findings 배열을 유지한다. [출고 기록 예시](release-record.md#실제-검수-기록)를 따른다.

J/K는 전 페이지의 소유 담당자를 중복·누락 없이 배정하고, 각 인접 경계에는 최소 한 건의 유효한 실제 관찰을 연결한다. 1~10쪽 담당자가 11쪽을 문맥으로 함께 보고 10/11 경계를 맡거나, 11~20쪽 담당자가 10쪽을 문맥으로 보고 맡아도 유효하다. 서로 다른 실제 reviewer_id와 execution_id를 가진 두 담당자가 같은 경계를 독립 관찰해도 허용하고, 완료 경계는 집합으로 한 번만 센다. 어느 관찰도 양쪽 페이지에 실제 접근하고 한 쪽 이상을 소유해야 한다. 같은 receipt 안의 경계 중복, 같은 실제 검수자 또는 실행의 중복 관찰은 거부한다. 관찰 중 하나라도 PENDING·FAIL 등 PASS 이외 상태이면 다른 PASS로 덮지 않고 미완료로 유지한다. J/K 역할의 독립성, 원본 기록·파일 해시·집계 연결도 보존한다.

Word 렌더 횟수는 고정하지 않는다. 실제 페이지 흐름을 확인하고, 결함이 남거나 DOCX가 다시 바뀌면 필요한 렌더/검수를 더 한다. DOCX 변경 없이 관찰·검수가 완료된 같은 렌더는 최종본으로 사용할 수 있다. NBSP·keepNext가 있어도 모든 잘림·빈 쪽 문제가 없어졌다고 간주하지 않는다. 글자·필기 공간을 줄여 횟수나 쪽수를 맞추지 않는다.

## 같은 현재 버전의 분할 기록만 집계

`review_coverage.py`를 `verify_release.py`가 호출한다. **기존 전체 검수 기록 방식도 계속 지원한다.** 분할 집계는 같은 현재 패키지·원고 단계·FINAL·DOCX/PDF 해시에 연결된 실제 자식 기록만 받는다. 각 기록의 실제 reviewer_id·execution_id·범위·근거와 파일 해시는 그대로 보존한다. 집계 결과는 범위 메타데이터이지 가상의 전 범위 검수자가 아니다.

- L은 단위 누락·중복 없이 전부 커버하고 실제 전체 연결 검수 기록도 필요하다.
- M 묶음과 N 묶음은 각각 전 문항을 블라인드로 풀며, 두 묶음 사이 실제 담당자 ID와 실행 ID가 하나라도 같으면 거부한다. 공유 장문 연결 문제와 분량 검토 근거도 유지한다.
- J/K는 현재 PDF 전 페이지를 빠짐없이 배정하고 두 실제 역할, 상세 확인 쪽, 인접 페이지 연결을 확인한다.
- S와 R은 기존 실제 전체 검수 기록을 유지한다. 부분 자료나 합성 시험 기록을 실제 승인으로 연결하지 않는다.

새 재검 실행의 ID가 달라지면 새 실제 기록을 만들고 역사 기록은 그대로 남긴다. **이 버전은 과거 PASS의 자동 상속이나 새 해시로 재바인딩하는 기능을 제공하지 않는다.** 변경분 자료는 수정 재검을 돕지만 단독으로 전체 FINAL/출고가 되지 않는다. 필수 단계 해시가 달라진 기존 승인은 자동 재사용하지 않고, 현재 버전에 대한 실제 완료 증거를 확보한다. 영향·증거가 불명확하거나 도구가 실패하면 기존 전체 검수로 돌아간다.

## R 대조와 기록량

`check_release_text.py`는 현재 원고·계획·두 FINAL·실제 DOCX에 대해 기존 정밀 검사기를 재사용하고 결과를 짧게 모은다. 표지 수량·역할별 텍스트는 기존 canonical 계획/저장본 대조로 확인한다. PDF 텍스트·실제 글꼴 목록·줄 끝 ★/①~⑤ 분리 후보·자리표시/학생용 답 노출 후보를 제공한다.

PDF 대조에서는 공백/NBSP와 승인된 ‘★핵심’ 표식 내부의 U+FEFF만 정규화하고 실제 DOCX의 푸터 문구가 페이지 하단에 있는 경우에만 제외한다. 지정 표식 밖의 제어문자·본문 하단·깨진 글자를 마음대로 지우거나 바꾸지 않는다. DOCX·FINAL의 정밀 대조는 그대로 유지한다. 추출 순서·합자·특수 글꼴의 차이는 실제 페이지를 확인해야 할 경고다. 맑은 고딕·Times New Roman 이외 모든 글꼴을 오류로 단정하지 않는다. 추출 실패도 ‘정상’으로 처리하지 않는다.

R은 짧은 진단과 실제 원문·FINAL·DOCX/PDF의 대응, 남은 경고와 승인 상태를 확인한다. JSON만 읽고 실제 확인을 끝냈다고 하지 않는다. 새 보고서를 출고 기록의 `reports.release_text`에 연결하면 현재 파일로 다시 대조하고, 경고마다 실제 R의 해결/확인 기록을 요구한다. 기계 대조와 J/K/R의 판단은 서로 대체하지 않는다.

총괄에게는 ID·상태·문제 위치·짧은 근거·산출물 해시만 전달하고 큰 question_views, 원고 전체, 페이지 이미지는 필요한 담당 입력에서만 읽는다. 토큰 사용량을 기록할 때 캐시 읽기/새 입력/출력과 실제 호출 수를 구분한다. 절감률은 같은 난이도의 실제 제작에서 측정하기 전에는 보장하지 않는다.
