# QC_HANDOFF·FINAL TXT 구성

차례: 자료별 파일 → 문서 머리 → 지문 블록·작성 규칙 → 워크북 블록 → 문제 전용 블록.

## 자료별 파일

- 해석지·분석지: [교재명]_UNITXX_QC_HANDOFF.txt → [교재명]_UNITXX_FINAL.txt
- 워크북·문제·정답해설: [교재명]_UNITXX_문제_QC_HANDOFF.txt → [교재명]_UNITXX_문제_FINAL.txt
- `UNITXX`는 제X과의 신규 내부 관리 표기다. 기존에 확정된 내부 `LESSON04`·`4과` 등 과 표기는 바꾸지 않는다. 내부 인계 교재명에는 과목·출판사·저자가 구별되는 확정 표기를 사용한다. 신규 예: `영어2_YBM(박준언)_UNIT04_QC_HANDOFF.txt`. 교육과정은 실제 확인한 값을 문서 머리에 기록하며, 기존 내부 인계 파일명은 임의로 변경하지 않는다. 전달용 DOCX/PDF는 별도로 [workflow 파일명 규칙](workflow.md#파일명과-플랫폼별-저장)을 따른다. 파일명용 저자 약칭을 문서 머리의 공식 저자명으로 대체하지 않는다.
- 각 자료군의 내용은 UTF-8 TXT 하나에 완전하게 넣는다. 해석·분석과 문제는 서로 다른 QC/FINAL 파일이다. 이 분리는 DOCX를 둘로 만들라는 뜻이 아니다. 교재는 1번 단계의 동일 DOCX에 누적 반영하며 이 문서의 서식 정보 제외 규칙은 내용 TXT에만 적용한다. DOCX 반영·보존·검증은 `workflow.md`를 따른다.
- 이 문서는 원고 필드·배열 형식을 담당한다. 내용 판단은 `analysis-content.md`, 각주는 `gloss-rules.md`, 워크북은 `workbook.md`, 문항 편성·유형·출제는 `assessment-content.md`를 따른다. 수신·저장·역할 경계는 `workflow.md`를 따른다.
- QC_HANDOFF와 FINAL에는 교재 내용과 출처 식별 정보만 넣는다. 수정 기록·승인 대기 사항·문항 편성표·담당 팀의 완료 상태는 수정인계 등 원고 밖 문서에 둔다. 템플릿은 서식 기준이며 삭제한 활동을 복원하는 내용 근거가 아니다.

검수 전용 예외: `export_handoff.py 원고.json --assessment 문제_QC_HANDOFF.txt --qc-diagnostics`는 문항별 `LENGTH_REVIEW`·`LENGTH_COMPARISON`을 추가한다. 이는 교사용 검토 근거이며 학생용·블라인드·FINAL에 넣지 않는다. 해당 QC는 파일명만 FINAL로 바꾸지 말고, 최종 내보내기에서는 `--qc-diagnostics`를 빼고 생성한다. 기본 내보내기는 위 내용 전용 규칙을 유지한다.

공유 지문의 `ANNOTATIONS`는 번호 삽입 전 변형 지문에서의 원시 `span`을 보존하고 `text`로 해당 낱말을 병기한다. `ANNOTATIONS_BASIS`를 확인하며, 이 숫자를 번호가 이미 붙은 표시 지문에 그대로 적용하지 않는다. 순서 문제의 A/B/C 블록 내부 개행은 Word와 같이 공백으로 출력하지만 블록 구분·권위 원문·위치 데이터는 유지한다.

## 문서 머리

    [교재명] 영어2 YBM(박준언)
    [과목] 영어2
    [출판사·저자] YBM(박준언)
    [교육과정·판본] 원본 또는 사용자 지정에서 실제 확인한 값
    [UNIT] UNIT04
    [학생용 과 표시] 4과
    [권위 원문] 사용자 지정 교과서 본문 파일명과 실제 쪽/영역
    [자료 범위] 혼공해석지 + 지문분석지

문서 머리의 교재명은 [공통 표시 기준](manuscript-data.md#해석지-헤더의-표시-정규화)에 따라 과목과 출판사·저자를 공백으로 연결한다. 파일명의 밑줄·저자 약칭을 표시 제목으로 복사하지 않는다. 내부 인계 파일명·관리 ID는 기존 workflow 기준으로 보존하고 학생용 과 표시는 `3과`·`Special Lesson 1`처럼 따로 파생한다. 위 교재는 이름 형식의 예시이며 현재 교재로 고정하지 않는다. 실제 원본이 PDF·DOCX·이미지·TXT 중 무엇인지에 맞게 파일명을 적는다. 교육과정·판본을 확인할 수 없으면 그 필드는 생략하고 미확인 사항은 원고 밖 검수 기록에 남긴다. 자료 범위에는 실제 포함한 부분만 적으며 대화·듣기·쓰기·추가 읽기를 임의로 포함하지 않는다. 폐지된 노란 도입 질문과 `[흥미 훅]` 필드는 인계에 넣지 않는다.

## 작성 규칙

- `SOURCE`는 과 안의 실제 독립 본문을 식별한다. 예시의 문단·문장 수는 복사하지 않으며 실제 범위로 바꾼다. 같은 독립 본문을 여러 공통 단위별 학습 단위로 나누더라도 `SOURCE`는 동일하게 유지한다. `[학습 단위]`는 `analysis-content.md`의 사용자 묶기 규칙에 따라 확정한 공통 단위이며 해석지·분석지·워크북의 범위를 1:1로 맞춘다. 원문에 없는 EBS식 ANALYSIS·Practice 구획을 만들지 않는다.
- `[분석 단위]`는 해당 공통 학습 단위와 같은 범위다. 원문 단락 경계는 보존하고 소제목 전체 묶기 결정에 따라 여러 원문 단락을 한 단위로 연결한다. 소제목 없는 짧은 원문 단락의 범위는 원문으로 확인한다. SOURCE_RANGE에 실제 범위를 기록한다. 각 블록은 제목 또는 주제 하나·의도·흐름·쉬운 풀이·어법·유의어/반의어 3세트를 갖춘다. 모든 공통 단위가 원문 모든 문장을 누락·중복 없이 포함해야 한다. 내부 SOURCE 식별자는 보존하고 학생용 단락 구분은 문단 1, 문단 2처럼 MASTER 기준으로 표시한다.
- 실제 소제목·문단 구분과 문장 순서를 보존한다. 원문에 문장 번호가 없으면 작업 범위에서 원문 순서대로 번호를 부여하고, 학습 단위의 문장 번호와 원문 범위를 혼동하지 않도록 대응을 기록한다.
- 위 제목·주제 서식은 선택지를 보여 주는 예시다. 실제 원고에는 해당 공통 단위에 어울리는 `[제목]` 또는 `[주제]` 한 줄만 남기고 영어와 한국어를 함께 쓴다. ‘또는’이라는 설명과 미선택 항목은 넣지 않는다. 별도 `[분석 제목]`을 덧붙이거나 같은 제목/주제를 지문 머리와 분석 머리에 중복 출력하지 않는다. 기존 원고의 두 필드를 읽을 때도 적절한 하나만 남긴다.
- `[S/V]`는 필드 이름이다. 필드 안에서는 같은 절의 주어·동사를 콤마로 구분하고 절 사이에만 `／`를 쓴다. 혼공 끊어읽기의 `/`와 혼용하지 않는다. 절별 S·V/S′·V′ 및 관계사·생략 표기의 판단은 `analysis-content.md`를 따른다.
- 분석 기본 3개와 승인된 결합 공식 대표 보충을 구별해 보존하고 각 항목의 학습 내용을 같은 순서의 워크북 구문 연습에 연결한다. 원고 근거·공식 ID·연습 연결은 manuscript-data.md를 따른다.
- 새 TXT의 기본 항목명은 글의 흐름·각 문장 쉬운 풀이·구문으로 해석하기다. 기존 FLOW·TOM_EASY·각 문장별 쉬운 풀이 키와 이전 표시명 `[어법 포인트]`는 읽기 호환으로 처리한다. 내부 `grammar_points`·`analysis_grammar_heading` 등 키는 그대로 유지한다. DOCX 표시명과 간격은 layout-rules.md 및 내장 MASTER를 따른다. TXT의 빈 줄로 시각적 간격을 대신하지 않는다.
- 지문 블록의 [각주]는 혼공해석지 전용이다. 지문분석지나 워크북·문제로 옮기지 않는다.
- 관계대명사·관계부사절의 연결은 생략 여부와 무관하게 `[구조 힌트]`에서 대조한다. 각주·S/V만 있다고 해당 힌트를 생략하지 않는다. 공통 원고의 `reading_checks.relative_gloss_ids`와 실제 원문 판정을 대조하되, 필드 누락·구형 검사 통과를 관계사 힌트 적용 완료로 보고하지 않는다.
- `[구조 힌트]`가 없는 문장도 접속사절·명사절·간접의문문·생략 등 어려운 해석 연결을 확인한다. 필요한 힌트를 보완하고 미선정 이유는 내부 `reading_checks.review_record`에만 남긴다. 학생용·FINAL에 ‘힌트 없음’이나 검수 판단을 추가하지 않는다. 실제 표시와 최대 수량은 `analysis-content.md`를 따른다.
- 일반형 `[구조 힌트]`는 `analysis-content.md`에 따라 `영어 → 한국어 해석 (structure_label)` 한 줄로 쓴다. 연결 부분을 같은 대괄호로 표시하고 한국어 어순에 맞는 위치에 둔다. 접속사·명사절·간접의문문·관계절 힌트는 연결어와 실제 S′·V′까지만 내보낸다. 주격 관계사는 V′만, be동사는 최소 보어만 예외로 남긴다. 관계사 앞 명사와 가주어 It~that 틀은 보존하되 일반 명사절 바깥의 means·have found와 동사 뒤 목적어·전치사 대상의 해석을 FINAL에서 다시 붙이지 않는다. 동명사·분사·부정사 자체의 한 문법 연결에 필요한 최소 범위는 유지하되 안쪽 동사 구문을 함께 풀지 않는다. FINAL도 문법 연결 우선·한 힌트 한 초점을 유지하며, `way [to stop] → [막을] 방법`에 stop A from V-ing의 전체 해석을 되붙이지 않는다. `display_mode:split-phrasal-verb`는 일반형 이름표·대괄호를 유지한 `[after you throw … away] → [여러분이 버린 후에]`처럼 출력하며, 이 목적어 생략을 다른 내부 어구 생략으로 확대하지 않는다. 표시 대괄호를 실제 절 전체의 경계로 설명하지 않는다. 구조 이름표는 마지막 한국어 뒤에 한 번만 붙이며, 내부 `explanation`을 설명문으로 내보내지 않는다. 문장당 최대 2개이며 두 개는 각각 `[구조 힌트]`로 시작한다. 짝 구조는 `[구조 힌트] both to hide … and to secretly crawl up to … → 숨기 위해서도 … 몰래 기어서 다가가기 위해서도 …`처럼 선택한 원문 부분과 그 부분의 뜻만 한 줄로 내보낸다. 짝 구조의 display_pairs는 정확히 1개이며 이름표·설명문·문장 전체의 완성 해석을 덧붙이지 않는다. 수동·능동 완료의 기능 결합 힌트는 `category:function-combination`, `display_mode:verb-function`에 `lexical_step`을 연결하여 `produced(생산된) → is produced(생산된다) (be p.p.)`, `find(발견하다) → have found(발견했다) (have p.p.)`처럼 한 줄로 표시한다. 왼쪽 낱말 뜻과 오른쪽 실제 동사구 결합 뜻을 구별하며 수동 뜻을 두 번 더하지 않는다. 실제 시제·태·부정·양태와 표시 범위 안의 부사는 보존하고 주어·목적어·A/B 틀·by/for 구는 덧붙이지 않는다. 공식 `formula_label`과 낱말 뜻 괄호는 보통 글씨다. 일반 진행·완료진행 등 이번 p.p. 구별 밖의 기존 힌트와 `what to V + do → 무엇을 해야 할지`는 현행 형식을 유지한다. 기능 결합 display_pairs는 정확히 한 쌍이며, 승인된 lexical_step은 같은 줄의 접두 낱말 뜻이지 추가 대응 쌍이 아니다. 모든 유형은 수동 줄바꿈을 넣지 않으며 Word의 자연스러운 줄 감김은 허용한다. 문법 기능이 드러나는 직역을 우선하고, 영한 양쪽의 같은 문법 기능 강조 위치를 공통 원고의 `emphasis_links`에 보존한다. DOCX는 영어 기존 색·한국어 검정의 보통 글씨를 기본으로 해당 대응 부분과 선정 공식의 S′/A 주어 조사 이/가에 강조를 적용한다. 명시적 `ko-only-verb-construction` 동사 결합은 영어만 보통 글씨로 두며 양쪽 내부 링크와 한국어 공식 뜻 강조는 유지한다. FINAL에는 이 표시 정책의 이름이나 강조용 기호를 덧붙이지 않는다. 대괄호 전체나 대응하지 않는 조사를 강조하지 않는다. 생략 관계사는 `display_mode:omitted-relative`에 따라 `a few solutions [(that) we can find] → [우리가 찾을 수 있는] 몇 가지 해결책`처럼 괄호 표지까지 FINAL에 보존한다. `(that)`는 구조 힌트에만 보충한 학습 표시이며 실제 that/which/who/whom/when/where/why 선택 및 최소 한국어 문법 대응은 원고에 기록한다. DOCX에서 괄호는 보통, 관계사 글자와 한국어의 최소 문법 대응 부분만 굵게+밑줄이다. 이 생략 관계사에는 빈 링크를 허용하지 않는다. 생략 명사절 접속사 that은 관계사와 구별해 `display_mode:omitted-conjunction`, `omitted_conjunction:that`을 사용한다. 힌트에만 `[(that) laws had to be changed] → [법이 바뀌어야 한다고] (명사절 접속사 that 생략)`처럼 표시하고, 괄호는 보통·that 글자와 실제 S′의 이/가 및 연결 어미는 굵게+밑줄로 대응한다. 생략 관계사는 기존 `omitted-relative`를 유지한다. 두 유형 모두 빈 대응 링크로 대체하지 않고 원문·청크·S/V·각주·자연 해석에 보충 표지를 추가하지 않는다. 생략된 주어·to까지 이 예외를 확대하지 않는다. 생략 주어 등 승인 범위 밖의 실제 대응이 없어 비운 링크의 `emphasis_note`는 내부 근거이며 FINAL에 출력하지 않는다. 승인된 관계사·접속사 표지와 시제태 공식·lexical_step 뜻 괄호 외에 강조용 따옴표·괄호·별표를 추가하지 않는다. 미제공 문장에는 필드와 ‘없음’ 표시를 생략한다.

- 모든 문장을 원문 순서대로 싣는다.
- 끊어읽기는 확정 원문 위치에 대응시킨다. 원문 위치의 조각과 원래 구분 공백을 복원했을 때 철자·대소문자·축약형·따옴표·구두점이 정확히 같아야 한다. 원문의 원숫자·위첨자를 편집 메타기호로 오인하여 삭제하지 않는다.
- 분석 영어와 한국어 끊어읽기의 조각 수를 맞춘다.
- 위와 같음, 동일, 생략 같은 참조 표현을 쓰지 않는다.
- 원래 문항 유형은 교재 원고에 표시하지 않는다. 실제 원본이 문제인 경우에만 출제 제외 유형 확인에 필요한 원래 유형을 문항 편성표에 기록한다. 독해 본문에 없는 원래 유형을 만들어 넣지 않는다.
- `===== [/지문] =====`은 TXT의 지문 종료를 나타내는 내부 표지로 유지하며 DOCX/PDF 본문에는 출력하지 않는다.
- 별도 모범 해석 부분과 별도 직역 줄을 넣지 않는다. 분석지 본문의 영어·한국어 끊어읽기 및 자연 해석이 그 역할을 맡는다. 한국어 청크와 자연 해석은 매 문장 별도로 관리하며 서로 대체하지 않는다.
- 워크북은 문제 제작의 필수 구성이다. 워크북 전체와 문제·정답해설은 아래 문제 전용 파일 하나에 둔다. 해석·분석 FINAL에 뒤섞어 넣지 않는다.
- FINAL은 수정 사항이 모두 반영된 완전한 내용본이어야 한다.
- 저장 뒤 다시 열어 문서 머리, 첫 지문, 마지막 지문, 파일 끝을 확인한다.

## 워크북 블록

문제 전용 파일에는 확정 공통 단위별 워크북을 먼저 넣고 미니 모의고사 1·2·3회를 이어 붙인다. 회당 문항 수는 공통영어1·2에서 5문항, 영어II(영어2)에서 7문항이다. 각 공통 단위의 워크북에 유의어·반의어 의미 판단용 실전문제 Q 블록 1개를 둔다. 워크북은 WB01부터, 객관식 실전문제는 파일 전체에서 Q01부터 중복 없이 번호를 매긴다. 대상 공통 단위가 P개이면 워크북도 P개이며, 공통영어1·2는 워크북 P문항 + 모의 15문항 = 총 P + 15문항, 영어II는 워크북 P문항 + 모의 21문항 = 총 P + 21문항이다. 사용자 지정 수량 예외는 실제 편성표를 따른다. 학습용 낱말 목록·구문 결합 연습·핵심 문장 활동을 객관식 문항 수에 섞어 세지 않는다. 실제 회차·문항 수·SOURCE·대상 공통 단위·SOURCE_RANGE·TYPE은 원고 밖의 문항 편성표와 일치시킨다. 편성표의 필수 항목은 `assessment-content.md`를 따른다. 공통 단위마다 확정 유반 3세트와 핵심 2문장을 연결한다. 짧은 공통 단위의 승인 수량 예외는 실제 제공 수·답안·제목·번호를 일치시키고, 대상 공통 단위·항목별 기준 수와 실제 수·사유를 원고 밖 기록과 사용자 보고에 남긴다. 유형 반복은 허용하되 문항 복제 여부와 전체 유형 다양성을 확인한다.

    [WB01]
    SOURCE:
    실제 독립 본문 식별자
    LEARNING_UNIT:
    실제 확정 학습 단위 식별자
    SOURCE_RANGE:
    실제 영역·문단·문장 범위
    [1. 오늘의 낱말]
    영어 표현과 뜻 쓰기 발문
    [2. 유의어·반의어 뜻 쓰기]
    해당 공통 단위 FINAL의 확정된 3세트에서 개별 어휘를 섞어 제시하고 뜻 쓰기 발문
    [3. 실전문제]
    해당 공통 단위의 유의어·반의어를 영어 선택지에 활용한 완전한 Q 블록 1개
    [4. 구문 결합해서 해석하기]
    분석의 각 기본·보충 항목 순서대로 번호가 붙은 실제 영어 구절·해석 빈칸을 먼저 두고, 바로 아래 도움말에 주초점 공식·문맥 뜻, 필요한 보조 기능·낱말 뜻을 제공
    결합된 한국어 답은 학생용에 넣지 않음
    [5. 핵심 문장 2개 다시 해석하기]
    확정 핵심 문장 2개를 1, 2로 매긴 영어 원문·직접 해석 발문
    [/WB01]

    [워크북 정답]
    낱말·유의어/반의어: 활동별로 번호와 한국어 뜻만 담은 표
    | 번호 | 뜻 | 번호 | 뜻 | 번호 | 뜻 |
    | --- | --- | --- | --- | --- | --- |
    | 1 | 첫 번째 정답 | 2 | 두 번째 정답 | 3 | 세 번째 정답 |
    | 4 | 네 번째 정답 | 5 | 다섯 번째 정답 | 6 | 여섯 번째 정답 |
    4번 구문 결합: 학생용 연습과 같은 순서의 번호와 결합 해석만
    5번 핵심 문장: 1, 2 번호와 우리말 해석만

- 위 워크북 블록의 수량은 기본값이다. 짧은 공통 단위에서 원문 근거로 가능한 수만 제공하는 예외는 `analysis-content.md`·`workbook.md`를 따른다. 핵심 문장이 1개이면 제목도 ‘핵심 문장 1개 다시 해석하기’, 학생용·답안 번호도 1개로 맞춘다. 예외 자체를 미완성 원고로 보지 않는다.
- 위 블록에 실제 내용을 빠짐없이 쓴다. 핵심 낱말은 최대 8개, 유의어·반의어는 3세트이며 상세 기준은 references/workbook.md를 따른다.
- 1·2·3·5번 학생용에는 품사·뜻·각주·구조 힌트·관계별 묶음·화살표·등호·미리 표시한 S/V·끊어읽기 등 힌트를 넣지 않는다. 승인된 4번 구문 결합 연습은 공식·문맥 뜻과 낱말 각주 뜻을 제공하는 예외이며 결합 답은 정답지에만 넣는다. 원 동사 구문의 불필요한 A/B 풀이 또는 묶음 각주의 연습 범위 밖 부분을 좁힌 지원은 manuscript-data.md의 검토된 support_overrides만 따른다. 낱말 활동과 해당 정답표 번호는 지문별·활동별로 1부터 시작한다. 핵심 문장 활동·답안은 원문 문장 번호 대신 1부터 실제 수까지 매긴다(기본 1, 2). 원문 문장 번호와의 대응은 원고 밖 연결 자료 점검에 사용한다.
- 워크북 낱말·문장 활동에는 EVIDENCE·EXPLANATION·WRONG_ANALYSIS를 요구하지 않는다. 그 활동의 답안과 객관식 실전문제의 상세 해설을 구분한다. 출처와 문항 번호는 유지한다.
- 실전문제 Q 블록은 워크북 안에 한 번만 전문을 넣는다. 문제 묶음에서 다시 복제하지 않는다.
- 내용 구분용 제목과 활동 발문은 유지하며, 쓰기 칸의 높이·선·여백 등 조판 정보는 넣지 않는다.

## 문제 전용 블록

문서 처음에 정확한 교재명과 UNIT을 쓰고, 실제 문항 순서에 따라 전체에서 중복 없는 Q01부터 번호를 매긴다. SET으로 워크북 실전문제·미니 모의고사 회차를 구별한다.

    [Q01]
    SET:
    워크북 실전문제 또는 실제 미니 모의고사 회차
    SOURCE:
    UNIT04-본문 등 실제 독립 본문 식별자
    SOURCE_RANGE:
    본문 2~3문단, 원문 문장 5~12 등 실제 출제 범위
    TYPE:
    assessment-content.md의 유형표에 맞춘 실제 유형
    QUESTION:
    완전한 발문
    GIVEN:
    삽입의 주어진 문장 또는 순서의 주어진 글
    PASSAGE:
    문제용 지문 전문(허용 조건을 충족한 교과서 발췌 원문 가능)
    BLOCKS:
    (A) 원문 블록
    (B) 원문 블록
    (C) 원문 블록
    TARGET:
    밑줄 대상으로 지정한 원문 표현 또는 번호별 어휘
    CHOICES:
    ① 첫 번째 선지
    ② 두 번째 선지
    ③ 세 번째 선지
    ④ 네 번째 선지
    ⑤ 다섯 번째 선지
    ANSWER:
    정답 번호
    EVIDENCE:
    정답을 지지하는 실제 원문 표현과 그 위치·논리 연결
    EXPLANATION:
    학생 수준의 정답 해설
    WRONG_ANALYSIS:
    정답을 제외한 네 번호별 개별 오답 이유
    CHOICES_KR:
    영어 선지 5개의 번호별 한국어 해석

- GIVEN·BLOCKS·TARGET은 해당 유형에만 둔다. 학생용 문제에서는 보이지 않을 검수 메모나 조판 지시를 넣지 않는다. TARGET은 발문에 필요한 밑줄 대상의 내용 지정이다.
- `SOURCE`는 같은 독립 본문의 모든 문항에서 같아야 한다. 발췌 길이·위치·학습 단위가 달라도 독립 본문 식별자는 유지한다. `SOURCE_RANGE`에는 실제 영역·문단·원문 문장 범위를 기입한다. 같은 단락·발췌 구간을 포함해 TYPE 반복은 허용하며 문항 자체의 복제는 피한다. 워크북 유형 제한과 미니 모의고사의 수능 유형 다양화는 `assessment-content.md`를 따른다. 독해 본문의 일부를 추가 읽기나 별도 독립 본문으로 바꿔 부르지 않는다.
- 순서는 GIVEN+BLOCKS, 삽입은 GIVEN+PASSAGE를 합쳐 출제 범위의 원문 전체가 포함되게 한다. 전문을 다시 중복하지 않는다. 교과서 문제용 지문은 references/assessment-content.md의 해당 학년·동유형 공식 모의고사 분량 기준과 출처 범위를 확인하고, 원고 밖 편성표에 실제 단어 수를 기록한다.
- 미니 모의고사에서 무관한 문장·삽입·어휘처럼 본문 ①~⑤가 선택지 역할을 하면 별도 CHOICES 목록은 생략한다. 정답과 네 오답 근거는 유지한다. 워크북 실전문제는 학습한 유의어·반의어를 활용한 영어 CHOICES를 제공하며 이 생략 규칙을 적용하지 않는다.
- CHOICES의 선택지는 영어로 작성하고 한국어 선택지는 만들지 않는다. 영어 선지 해석은 CHOICES_KR라는 해설 영역에만 둔다. CHOICES_KR에는 번호별 한국어 해석을 저장하고, 해설지 출력 시 CHOICES의 같은 번호 영어 원문 전체와 결합해 `① 영어 선택지 전체 (한국어 해석)`으로 표시한다. 상세 표기·유형별 기호 예외는 `assessment-content.md`의 문항 정보 기준을 따른다. 학생용 선지에는 번역을 붙이지 않는다.
- 모든 Q 블록에는 단어 각주를 넣지 않는다. 기존 VOCAB_GLOSS 등 단어 각주의 제목과 내용을 모두 삭제한다.
- 이 문제 전용 Q 블록의 실전문제에는 정답·근거·해설이 필수이며, 5지선다형은 네 오답 분석도 필수다. 워크북의 낱말·문장 활동은 위의 간단 정답 기준을 따른다.
- 빈칸은 밑줄 16자로 표시한다. 요약문은 본문 뒤 [요약문]에 (A)·(B)를 명확히 구분한다.
- 필요한 문항 정보와 낱말 정답표의 실제 데이터를 넣는다. 로고·쪽 번호·머리말/꼬리말·글꼴·색상·여백·장식용 표 디자인·쪽 나눔·장식·반복 안내·작업 기록은 제외한다.
- 자체검수 단계의 내용 원고는 문제_QC_HANDOFF로 저장하고, 동시에 동일 DOCX의 담당 부분에도 반영한다. 제작방은 문제_FINAL을 만들지 않는다. 별도 검수방이 확정하는 문제_FINAL도 워크북·문제·정답해설 전체를 포함하며 확정 수정은 같은 DOCX에 반영한다. 검수 후 제작방은 최신 FINAL을 기준으로 같은 DOCX를 이어 정리한다.


## DOCX 출력 번호와 MASTER 조판

Q01 등은 원고 전체에서 유일한 내부 ID다. 학생용 출력 번호와 구별하며, 워크북 실전문제와 미니 모의고사 번호를 분리하고 미니 모의고사는 각 회차마다 1번부터 시작한다. 정답표와 해설도 회차+회차 내 번호로 일치시킨다. 각주의 필수 낱말 별표는 확정 오늘의 낱말 목록과 연결한다. 글자 크기·간격·표·답안 공간·페이지 흐름·렌더 검수는 `layout-rules.md`를 필수 적용한다.


## 기계 입력과 TXT의 관계

같은 내용을 JSON과 TXT 두 곳에서 따로 수작업으로 고치지 않는다. 확인된 내용 데이터에서 TXT를 파생하거나, 검수된 TXT를 읽어 공통 데이터로 변환한 뒤 필드·원문·수량을 대조한다. 변환 전후의 입력 해시와 범위를 기록한다. 형식만 바뀐 파일을 새로운 독립 검수 결과라고 부르지 않는다.

영어 청크는 원문 문자 위치와 한국어 청크를 연결하고, S/V는 검토된 절 종류·시작 위치·이끄는 말·실제 주어/동사 위치로 관리한다. 위치는 Unicode 코드 포인트 기준이며 JSON의 UTF-8 바이트 위치나 JavaScript UTF-16 인덱스와 혼동하지 않는다. 표시용 `/`·`／`·`—`는 데이터 분할 근거로 쓰지 않는다. 기존 TXT를 읽을 때 원문 안의 같은 기호와 편집 기호를 구별한다.

별도 모범 해석·직역 필드는 옛 입력의 이관 참고로 읽을 수 있지만 새 학생용 출력에 되살리지 않는다. 자연 해석 누락을 옛 직역 값으로 자동 보충하지 않는다. 필요한 해석은 언어 검수 단계에서 확정한다.

## S/V 축약형 예외 U53

축약형은 S/V에도 원문 형태를 유지한다. 단, `'s`가 has의 축약형이면 `'s(has)`로 병기한다(U53). 예: `It's clear.` → `S: It, V: 's`, `It's changed.`(has changed) → `S: It, V: 's(has) changed`. 곡선 아포스트로피 `’s`도 원문 모양을 유지해 `’s(has)`로 표시한다. is/has는 문맥에서 확인하며 과거분사가 뒤에 있다는 이유만으로 has로 판정하지 않는다. 원문 영어·청크는 바꾸지 않고 표시용 설명을 분리한다.

기계 입력의 각 절에는 동사 범위 안 `'s`/`’s`마다 `contraction_readings: [{span: [start, end], expanded: is 또는 has}]`를 둔다. 실제 JSON의 expanded 값은 문자열이다. 원문 문장 내부의 코드 포인트 위치를 사용한다. 해석을 자동 추정하지 않으며 미확인 항목은 오류로 남긴다. is는 표시를 추가하지 않고 has만 병기한다.

## 공유 장문 인계

이 문서의 QC/FINAL은 항상 담당 범위 전체 인계다. 별도 [부분 검수 자료](review-efficiency.md)는 `--review-packet` 출력 JSON에만 저장하며, `--changed-only`로 FINAL을 일부만 내보내지 않는다. 문항 블라인드 풀이에는 답·해설·원문 정상 순서가 포함된 이 전체 교사용 인계본을 먼저 전달하지 않는다. 실제 풀이 기록을 저장한 뒤 대조 단계에서 제공한다.

매회 마지막 두 Q 블록은 같은 `PASSAGE_GROUP` ID로 연결한다. 앞에 `[PASSAGE_GROUP 그룹ID]` 블록을 한 번 두고 QUESTION_IDS, SOURCE, SOURCE_RANGE, 실제 인쇄 PASSAGE, ANNOTATIONS를 완전히 기록한다. 공유 PASSAGE는 어휘 표적·오답 치환을 포함한 실제 출력본이다. 각 Q 블록은 자기 발문·선지(있는 유형)·답·근거·해설·오답 분석을 모두 갖추되 같은 PASSAGE를 중복하지 않는다. 공통 JSON의 문항별 복원 원문과 공유 출력 지문을 혼동하지 않는다. 함축 의미 발문의 PROMPT_UNDERLINES는 발문 내부의 실제 목표 범위를 보존한다. 밑줄·유형 표시는 내용 정보이며 임의 조판 메모와 다르다.

공통 JSON의 `length_review`와 `learned_relation_uses`는 실제 원문·선택지 연결에 대한 검수 기록이다. TXT만 수정하여 연결을 지우지 말고 JSON을 함께 갱신·검증한다. 원고 밖 편성·검수 기록에서 공식 분량 비교 및 짧음 검토를 확인한다.
