# 교과서 공통 제작 스킬

공통 내용 규칙·MASTER 역할 조판·원고 연결·저장본 대조를 한 패키지로 제공한다. [검증 범위](references/verification.md)를 확인한다. 로컬 구조·Word 시험을 다른 플랫폼에서의 실제 실행이나 교재의 독립 내용 검수로 확대하여 보고하지 않는다. 썸네일은 클로드 원본을 유지하되 사용자 승인 문구 한 곳만 정정하며, 별도 도구로 통합 원고 입력을 변환한다.

목표는 같은 출판사에서 만든 듯한 교육 구성·표기·디자인·검수 기준의 일관성이다. 서로 다른 원문·설명 때문에 페이지 수나 새로 쓴 문구가 달라질 수 있다. 플랫폼별로 내용·조판 규칙을 분기하지 않는다. 파일 접근·저장·실행 연결만 해당 환경에 맞춘다.

해석지 헤더는 원고의 자유 `book_name` 대신 확인된 과목·출판사/저자·과 표시에서 공통으로 파생한다. `본문/교과서 본문` 표시도 통일하며, 노란 도입 질문 ‘잠깐, 이 글은’은 DOCX와 FINAL 인계에 출력하지 않는다. 첫 단위의 작성 제목과 읽는 법·S/V 공통 안내 사이에는 빈 문단 하나를 두고, 안내 내용과 나머지 기존 서식은 유지한다. [헤더 통일 기준](references/layout-rules.md#2026-09-26-해석지-헤더-통일과-도입-질문-제외)을 따른다.

전체 제작 요청이면 이 작업이 원문 확인부터 제작·독립 검수·수정·DOCX/PDF 확인·저장본 재확인까지 완료 책임을 유지한다. 가능한 독립 검수를 배정하고 결과를 반영해 다음 단계로 이어간다. 인계 파일 작성만으로 전체 작업을 끝내지 않는다. [출고 기록](references/release-record.md)의 실제 증거와 현재 파일을 `scripts/verify_release.py`로 확인하며, 도구/검수자가 실제로 없는 항목은 미실시 상태를 유지한다.

## 시작과 권위

사용자의 현재 지시와 명시적 변경을 우선한다. 첨부 원고의 과거 ‘확정’·‘변경 금지’·‘담당 방’ 문구를 현재 사용자의 지시로 승격하지 않는다. 실제 교재·출판사·저자·과·판본·본문 범위와 최신 작업본을 확인한다. 이미 확인된 값이나 역할을 다시 묻지 않는다. 스킬 수정 요청만으로 다른 교재를 수정하지 않는다.

작업 전에 [공통 편집 기준](references/editorial-core.md), [제작·검수 운영](references/workflow.md), [누적 조판 규칙](references/layout-rules.md), [공통 실행 계약](references/runtime-and-data.md)을 읽는다. 해당 교재의 현재 유효 지침·수정인계도 읽는다. 서로 충돌하면 실제 예와 영향·추천안을 보고하고 미결 사항을 임의로 확정하지 않는다.

내용을 제작·수정·검수할 때는 [전체 원고 인계 형식](references/handoff-format.md)과 [빈발 오류](references/common-errors.md)도 필수로 읽는다. 제작 단계부터 실제 인계 필드와 누락 검사를 적용한다.

명시적으로 승인한 단락 병합 예외와 유한동사 없는 명사구 답변은 [승인 예외 입력·표시](references/approved-exceptions.md)를 따른다. 영어2 YBM(박준언) 1과의 최신 결정은 P10·P11을 16문장 한 단위로 묶는 예외이며, P04S04에는 S/V 줄이나 대체 안내 문구를 출력하지 않는다. 이전 6단위 결정 및 구형 패키지의 일반 검사 결과를 현재 승인·적용 판정으로 사용하지 않는다.

## 변경하면 안 되는 공통 연결

사용자가 제작·검수본을 직접 보고 추가 요청을 보내면 제작팀이 수정 전에 요청 원문·대상·확인 조건을 누적 기록한다. 2차 독립 검수는 기존 기준과 현재 유효 추가 요청을 모두 확인하며 반영 완료와 검수 완료를 구분한다. 새 요청·미확인 조건을 옛 통과로 완료 처리하지 않는다. [후속 검수 절차](references/user-feedback.md)를 적용하고 답을 드러낼 수 있는 요청 기록은 문항 블라인드 풀이 뒤에 전달한다.

- 원문 단락 중 6문장 이하가 있으면 해당 소제목 전체를 해석지·분석지·워크북의 공통 단위로 묶는다. 소제목 없는 짧은 단락은 실제 원문을 보고 묶음 범위를 확인한다. 원래 단락·문장 ID·순서는 유지한다.
- 공통 단위마다 혼공해석지 → 지문 분석 → 워크북 순서다. 분석지에는 모든 문장의 영어 청크 → 대응 한국어 청크 → 별도 자연 해석을 둔다. 이 본문 뒤 **새 쪽의 파란 분석 헤더** 아래 글의 의도·흐름·쉬운 풀이·어법·유반을 둔다. 별도 모범 해석 부분과 중복 직역 줄은 만들지 않는다.
- 구문으로 해석하기 한 항목은 학습 초점 하나만 다루고 제목·인용 범위·설명을 그 초점에 맞춘다. **구문 공식·문맥 뜻 → 각 자리에 실제 원문과 각 부분의 뜻 대입 → 핵심 결합 해석**을 보여 준다. S/V/A/B 등은 실제 해당 구조에 필요한 자리만 사용하며, 원문 전체를 다시 적고 번역하거나 추상적인 읽기 조언만 하는 것으로 대신하지 않는다. 품사·명칭·공식 소개나 문법 시험 판별 요령만으로 끝내지 않는다. 이 대입 설명은 분석지 구문으로 해석하기의 기준이며 별도 구조 힌트의 짧은 표시 방식은 유지한다. ‘각 문장 쉬운 풀이’는 기존처럼 단위당 원문 3문장을 선정하되, 원문 순서대로 앞 문맥과 글 속 역할을 연결해 중학생이 바로 이해할 말로 설명한다. 설명문은 한 문장에 한 내용을 담고 문장 수를 제한하지 않는다. [쉬운 풀이 작성·검수 기준](references/analysis-content.md#각-문장-쉬운-풀이)을 적용하며, 이 코너의 대명사·조사 다듬기를 구조 힌트·각주·S/V 규칙에 확대하지 않는다. 수동·능동 완료의 기능/낱말 결합은 상위 구조 힌트를 교체하지 않는다. 해당 문장에서 결합 힌트로 선정되지 않은 공식은 같은 단위의 ‘구문으로 해석하기’ 대표 사례에 연결한다. 기존 기본 분석 3개를 유지하고, 그 3개에서 아직 설명하지 않은 결합 공식만 대표 사례를 보충한다. 같은 단위·같은 공식의 보충 설명은 한 번만 둔다. 다른 문장에 같은 공식의 힌트가 있다는 이유로 해당 문장의 분석 연결을 생략하지 않으며, 기존 분석이 그 공식을 설명하면 그 항목에 연결하고 추가하지 않는다. 부분 부정처럼 해당 구절을 단순 기능 공식으로 연습하면 뜻이 바뀌는 경우에는 사용자에게 실제 예를 제시하고 승인받은 경우만 명시적 예외로 연결한다. 승인된 부분 부정 분석·연습은 유지하고 같은 단위의 다른 문장으로 수동 결합을 연습한다. 예외 범위·승인 근거·원래 항목과 대체 항목을 기록하며 부분 부정을 일반 부정으로 고치거나 임의 면제하지 않는다. 완료진행 등 이번 수동/능동 완료 구별 밖의 정책을 새로 확대하지 않는다. 분석의 기본 항목과 승인된 보충 항목을 모두 같은 순서의 워크북 ‘4. 구문 결합해서 해석하기’에 1:1로 연결한다. 학생용은 번호·영어 구절·해석 빈칸을 먼저 두고, 바로 아래 도움말에 배운 주초점 공식·문맥 뜻과 필요한 보조 기능·낱말 뜻을 제공한다. 문항과 해당 도움말은 함께 배치하고 다음 문항까지 묶지 않는다. 보조 기능은 같은 문장의 기존 각주 ID로 연결하며 학습 초점 자체를 바꾸지 않는다. 결합된 한국어 답은 정답지에만 둔다. 공식과 낱말 뜻은 기존 승인 내용과 일치시키며 원문 전체를 반복 해석하는 활동으로 늘리지 않는다. 동사 구문의 불필요한 A/B 풀이를 빼거나 묶음 각주의 실제 연습 낱말만 지원할 때는 manuscript-data.md의 검토된 support_overrides를 적용한다. 기본 항목의 실제 근거 부족 예외는 [분석 내용 기준](references/analysis-content.md)을 따른다.
- S/V는 콤마와 절 사이 전각 `／`를 사용한다. 주격 관계절은 V′만, 명령문은 생략된 You 없이 V만, 이끄는 말 없는 주절은 `[주절]` 없이 표시한다. has 축약인 `'s`만 `'s(has)`로 병기한다. 절 범위·is/has는 원문 문맥에서 확인한다. 긴 명사구 주어의 S/V 표시에서는 한정사·앞수식어·중심명사를 남기고 뒤수식어를 제외한다. 내부 `subject_spans`의 실제 전체 주어는 보존하며, 문법 검토 후 `subject_display_spans`와 `subject_display_review`로 표시 범위와 이유를 따로 기록한다. 명사절·동명사 주어, 부분/수량 표현, 등위 주어는 이 명사구 축약으로 의미·수·구조를 잃지 않게 전체를 유지한다.
- 각주는 혼공해석지에만 두며 일반 단어는 중1 수준부터 그 이상을 모두 제공한다. 단독 you는 대소문자와 무관하게 제외하되 원문·S/V는 보존한다. 수동·능동 완료는 기능 공식과 낱말을 나눈다. 수동의 낱말은 실제 p.p.형·수동 뜻(`be p.p. — ~되다 / produced — 생산된`), 능동 완료는 원형·기본 뜻과 실제 p.p. 관계(`have p.p. — ~했다 / find — 발견하다 (found는 find의 p.p.형)`)로 제공한다. 완료수동 `have been p.p.`는 수동이므로 실제 p.p.형을 유지한다. 전치사의 흔한 뜻으로 이해하기 어려운 `be provided with`·`be satisfied with` 등의 숙어는 한 각주로 유지한다. 독립 p.p.는 실제 형태·문맥 뜻(`held — 개최된`, `trained — 훈련받은`), 일반 정규과거 -ed는 원형·기본 뜻, 불규칙 과거는 현행 표기, 일반 -ing는 기존 기능/원형 분리를 유지한다. 이번 p.p. 구별 밖인 완료진행 `have been V-ing`와 오늘의 낱말 선정·표기는 별도 현행 규칙을 유지한다. 동사의 뜻을 완성하는 to V는 `decide to V — ~하기로 결심하다`, `struggle to V — ~하려고 애쓰다`처럼 동사 구문으로 묶고 V의 실제 낱말 뜻은 별도로 지원한다. 별도 목적이면 `use — 사용하다 / to V — ~하기 위해 / buy — 사다`로 나눈다. `had struggled to enter`는 `had p.p. — ~했다 / struggle to V — ~하려고 애쓰다 (struggled는 struggle의 p.p.형) / enter — 들어가다`다. 단독 to V에 `~하기로·~하려고·~하는 데`를 붙이지 않으며 문맥상 보충/목적이 불명확하면 실제 예와 추천안을 보고하고 답을 기다린다. 대명사는 `we — 우리는`처럼 실제 한국어 격에 맞추고 기능어는 문맥에 맞는 한 뜻을 고른다. 고정 숙어·가주어·기초어·전치사·지정 대명사·다의어·★의 상세 기준은 각주 참조를 적용한다.
- 실제 관계대명사·관계부사절은 생략 여부와 무관하게 구조 힌트에 포함한다. 전치사+관계대명사 각주는 `전치사 + 관계대명사 S′ V′ — S′(이/가) V′하는`으로 통일한다. 실제 문맥에서 이 틀을 적용하면 뜻·시제·관계가 손상되는 예는 강제로 고치지 않고 `reading_checks.review_record`에 원문·문장/각주 ID·적용 불가 이유·문맥상 뜻을 남겨 1차 L 독립 검수 때 사용자에게 보고한다. 일반 전치사·간접의문문·그 밖의 관계사에 이 통일 기준을 확대하지 않는다. 각주·S/V가 있다는 이유로 명시된 관계사를 빼지 않는다. 생략된 관계사는 구조 힌트에만 `[(that) …]`처럼 실제 관계에 맞는 괄호 표지를 보충하고, 관계사 글자와 한국어의 최소 대응 부분을 대응 강조한다. `display_mode:omitted-relative`와 `omitted_relative`를 사용하며 원문·청크·S/V·완성 해석은 바꾸지 않는다. 생략 명사절 접속사 that은 관계사와 구별해 `display_mode:omitted-conjunction`, `omitted_conjunction:that`을 사용한다. 힌트에만 `[(that) laws had to be changed] → [법이 바뀌어야 한다고] (명사절 접속사 that 생략)`처럼 표시하고, 괄호는 보통·that 글자와 실제 S′의 이/가 및 연결 어미는 굵게+밑줄로 대응한다. 생략 관계사는 기존 `omitted-relative`를 유지한다. 두 유형 모두 빈 대응 링크로 대체하지 않고 원문·청크·S/V·각주·자연 해석에 보충 표지를 추가하지 않는다. 생략된 주어·to까지 이 예외를 확대하지 않는다. 기존 힌트의 같은 관계는 중복하지 않고, 간접의문문·접속사와 실제 용법을 구분한다. 쉼표 뒤 계속적 which는 추가 설명·병렬이면 ‘그리고’, 실제 대조·전환이면 ‘그런데’로 문맥에 맞추고, 같은 구문의 각주·구조 힌트·분석지 해석에서 연결 의미를 일치시킨다.
- 구조 힌트가 없는 문장도 전부 확인한다. 접속사절·명사절·간접의문문·생략·목적어/보어 연결처럼 해석 연결이 어려운 구문이 있으면 필요한 부분의 짧은 힌트를 추가한다. 각주에 접속사 뜻이 있다는 이유로 연결 힌트를 생략하지 않는다. `throw away`·`feed on`처럼 그 자체 뜻을 익히는 숙어는 각주로 제공하며 그것만으로 구조 힌트 후보가 되지 않는다. `provide A with B`·`help A V`·`allow A to V`처럼 뒤의 대상·동사·준동사를 연결해 해석하는 동사 구문만 후순위 후보로 삼는다. 전치사나 불변화사가 붙었다는 이유만으로 모든 구동사를 후보로 삼지 않는다. 상위 after·that 힌트에서 동사 뜻을 보존하는 `throw … away`·`feed on` 범위는 그대로 유지한다. 상위 문법·짝 구조·필요한 동사 구문 후보가 없고 힌트가 비어 있으면 실제 수동태를 후순위 기능 결합 후보로 제공한다. `produced(생산된) → is produced(생산된다) (be p.p.)`처럼 낱말 뜻과 동사 부분만 표시하며 기존 상위 힌트는 유지한다. 수동태도 없는 문장을 단순 and/but 나열이나 기본 낱말로 억지로 채우지는 않는다. 실제 선정·미선정 이유와 최소 표시 범위는 [구조 힌트 기준](references/analysis-content.md#구조-힌트)을 따른다.
- 일반 구조 힌트는 `영어 → 한국어 해석 (structure_label)` 한 줄로 쓰고 영어·한국어의 대응 부분을 같은 대괄호로 표시한다. 한국어는 문법 연결이 보이는 직역을 우선하고, 영어·한국어 모두 보통 글씨를 기본으로 한다. 한 문법 기능의 실제 영한 대응을 `emphasis_links`로 기록한다. 선정 공식의 S′/A 주어 조사 이/가도 포함하고 고정어+ing를 빠뜨리지 않는다. 일반 문법은 양쪽 굵게·밑줄, 명시적 `ko-only-verb-construction` 동사 결합은 영어 보통·한국어 조사·연결 어미만 강조를 적용한다. 영어는 기존 색, 한국어는 검정을 유지하며 대괄호 전체·무관한 조사나 내용어를 강조하지 않는다. `of ↔ 의`, `using`의 `ing ↔ 사용하여`의 `하여`처럼 정확히 대응시킨다. 독립 p.p. 각주에 대응하는 힌트는 `held ↔ 개최된`처럼 낱말 뜻 전체를 양쪽 강조한다. by/without V-ing의 기능 강조에는 이 예외를 적용하지 않는다. 절 연결 힌트는 연결어와 실제 S′·V′까지만 보여 주고 동사 뒤 목적어·전치사 대상과 그 해석은 넣지 않는다. 주격 관계사는 V′만, be동사는 뜻을 연결하는 최소 보어만 예외로 남긴다. 관계사의 앞 명사와 가주어 It~that 틀은 유지하지만 일반 명사절 바깥의 means·have found 같은 동사는 빼며, 표시한 동사구의 시제·부정·양태는 보존한다. 힌트 하나는 문법 연결 한 가지에 집중한다. 관계사·접속사·명사절·준동사 수식 등 문법 연결을 먼저 고르고, stop A from V-ing·help A V·allow A to V·keep A B 같은 동사 구문과 기능·낱말 결합은 후순위로 둔다. 상위 문법을 보여 주면서 안쪽 동사 구문의 A/B와 완성 해석까지 함께 넣지 않는다. 동명사·분사·부정사 자체의 한 연결에 필요한 대상까지 일괄 삭제하지는 않는다. 분리 구동사 사이 목적어만 생략하는 일반형 예외도 아래 기준을 따른다. 한국어 뒤의 짧은 이름표는 한 번만 붙이며 긴 설명이나 읽기 지시로 늘리지 않는다. 짝 구조(`paired-structure`)는 원문에서 고른 대응 부분만 ` … `로 연결한 영어와 그 부분의 한국어 뜻을 한 줄로 보여 주며, 문장 전체 해석·이름표·설명문을 덧붙이지 않는다. 짝 구조는 기능 결합보다 먼저 검토하고 기존 선정 우선순위·문장당 최대 2개·포함 힌트 합치기를 유지한다. 수동·능동 완료의 기능 결합 힌트는 `category:function-combination`, `display_mode:verb-function`에 `lexical_step`을 연결하여 `produced(생산된) → is produced(생산된다) (be p.p.)`, `find(발견하다) → have found(발견했다) (have p.p.)`처럼 한 줄로 표시한다. 왼쪽 낱말 뜻과 오른쪽 실제 동사구 결합 뜻을 구별하며 수동 뜻을 두 번 더하지 않는다. 실제 시제·태·부정·양태와 표시 범위 안의 부사는 보존하고 주어·목적어·A/B 틀·by/for 구는 덧붙이지 않는다. 공식 `formula_label`과 낱말 뜻 괄호는 보통 글씨다. 일반 진행·완료진행 등 이번 p.p. 구별 밖의 기존 힌트와 `what to V + do → 무엇을 해야 할지`는 현행 형식을 유지한다. 여러 단계로 나누지 않는다. 모든 유형은 수동 줄바꿈 없이 작성하고 Word의 자연스러운 줄 감김은 허용한다. [구조 힌트 작성·검수](references/analysis-content.md#구조-힌트)를 따른다.
- 구조 힌트의 표시 영어에 실제 지시 대명사가 있으면 한국어 대명사를 남기고 바로 뒤에 문맥에서 확인한 `[지칭 대상]`을 붙인다. `그것들[문어들]이`, `우리[인간들]가`, `그것[문어]의`처럼 단복수와 대명사 기준 조사를 맞춘다. 대명사·참조어·참조 괄호는 보통 글씨이며 기존 문법 조사·어미의 대응 강조만 유지한다. `display_pairs.pronoun_refs`로 명시한 한국어 참조 괄호만 문법 괄호 집계에서 제외한다. 가주어·비인칭 it, 관계사·접속사, A/B, 지시 한정사는 제외하고 실제 명사를 대신하는 one류는 포함한다. 참조어를 추측하거나 `들`을 기계적으로 붙이지 않으며 본문·S/V·각주·정식 해석은 바꾸지 않는다. [대명사 참조 내용 기준](references/analysis-content.md#대명사와-지칭-대상), [표시 위치 계약](references/manuscript-data.md#구조-힌트의-대명사-참조)을 따른다.
- 3인칭 단수 일반동사의 **각주 표제어**는 `helps → help — 돕다`처럼 원형으로, 복수 명사는 `creatures — 생명체들`처럼 실제 복수형으로 제공한다. 묶인 동사 구문은 중심 동사만 원형으로 맞추고 묶음·뜻을 유지하며 be·has·does의 기존 기능 공식은 바꾸지 않는다. 품사·원형을 확인해 `verb_form.usage:third-person-singular`로 선언하고 s를 기계적으로 삭제하지 않는다. 해당 각주를 ID로 재사용하는 도움말에도 같은 표제어를 적용하되 원문·청크·S/V·구조 힌트·인용·실제 연습 영어와 오늘의 낱말 등 별도 어휘 활동은 보존한다. 기존 p.p.·-ed·-ing 정책은 유지한다. [활용형 기준](references/gloss-rules.md#실제-형태와-활용형)을 따른다.
- 명사 뒤 형용사구·전치사구 후치수식은 그 구 앞에서 끊는다. 단, 수량·종류+of가 뒤 명사 앞에서 같은 어순의 한국어 `~의`로 대응하면 `metric tons of — (미터법) 톤의`, `some kind of — 어떤 종류의`처럼 of까지 한 각주로 묶고 내부를 끊지 않는다. 일반 명사 후치수식에 확대하지 않는다. 수동태에서 ‘누가·무엇에 의해’를 나타내는 by 구도 by 앞에서 끊으며, 다른 용법의 by에 일괄 적용하지 않는다. 부분 부정 등 실제 의미 범위는 영어·한국어 대응에서 보존한다. 문맥상 확인한 가주어 It+that 진주어(예: `It seems/appears/is likely that S′ V′`)는 각주를 한 틀로 합치고 본문 It~that 사이를 끊지 않는다. that절 내부의 필요한 경계와 기존 to 진주어 앞 경계는 유지한다.
- 워크북은 오늘의 낱말 → 섞은 유반 뜻 → 실전문제 1개 → 구문 결합해서 해석하기 → 핵심 문장 해석이다. 기존 1. 오늘의 낱말 → 2. 유의어·반의어 뜻 쓰기 → 3. 실전문제를 유지하고 새 쪽에서 4. 구문 결합해서 해석하기 → 5. 핵심 문장 N개 다시 해석하기 순서로 이어 간다. 5번만 다시 강제 새 쪽으로 보내지 않으며 핵심 문장 제목·전체 활동을 함께 배치한다. 정답도 같은 4·5번에 연결하고 유반 0세트는 빈 2번만 생략하여 1·3·4·5를 유지한다. 단위 유반 학습 연결을 유지하되 보고된 유반 0세트는 어휘를 억지로 넣지 않고 일반 실전문제로 낸다. 문제 지문은 과 안의 적절한 연속 원문에서 학습 단락 경계와 무관하게 고른다. 필기 공간을 줄여 쪽수를 맞추지 않는다. 단순 낱말 정답은 번호 순서대로 테두리 없는 **3열**에 배치한다.
- 미니 모의고사는 기본 3회다. 영어2는 회당 일반 5+장문 2=7문항, 공통영어1·2는 일반 3+장문 2=5문항이다. 매회 마지막 두 문항은 공유 장문 한 세트이며 기본 유형은 표준 제목·문맥 어휘다. 다른 과목의 기본 총수는 5개이며 학년 분량 기준을 명시한다. 현재 사용자 지정 편성을 우선한다. 어법 문항은 제외하고 문장형 선지는 영어, 번역은 해설에 둔다.
- 문제 길이의 고정 100단어 조건은 폐지한다. 공통영어는 고1, 영어2는 고2의 **동유형 공식 모의고사 분량**을 기준으로 너무 짧지 않게 선정한다. 불필요한 원문으로 길이를 채우지 않는다. [분량 기준과 장문 계약](references/assessment-content.md)을 적용한다.
- 일반 문제 지문은 원래 문단 사이를 공백으로 연결해 한 문단으로 출력한다. 장문은 문단을 유지하고 순서는 주어진 글·A/B/C 구분을 유지한다. 순서 선지는 ACB·BAC·BCA·CAB·CBA로 고정한다. 내용 확인은 표준 일치/불일치 발문, 어휘 다섯 표적은 밑줄, 함축 의미는 본문과 발문 모두 같은 표현에 밑줄을 적용한다. 문제 사이 약 두 빈 줄의 여유를 두고 가독성을 Word에서 확인한다. 페이지당 두 문항을 강제하지 않으며 공유 장문도 앞 문제와 기존 서식으로 세트 전체가 들어가면 같은 쪽에 둔다. 현재 쪽에서 갈라지지만 새 한 쪽에는 들어갈 때만 세트 전체를 다음 쪽으로 옮긴다. 정답 근거는 선지 해석·오답 정리와 같은 제목 서식으로 따로 구분한다.
- 해석지 각 단위 끝에는 문장 번호 복습란을 둔다. 응원·명언 선택 기능, 별도 단어장, 수업용 2차 해석지, 분석지 내부 일반 단어·숙어 표는 제외한다. 원문 인용·분석 유반·워크북 낱말 활동은 유지한다.

## 하나의 MASTER와 실제 저장본

2026-09-25 후속 승인으로 실제 Word에서 넘친 분석 설명부·워크북 정답에만 [소폭 조판 조정](references/layout-rules.md)의 `spacing`→필요 시 `spacing_and_type` 두 프로필을 허용한다. 분석의 끊어읽기 본문·해석지·각주·S/V·필기 공간·표·표지·기존 문항 간격은 보존하며, 제목·유반 글자 크기도 유지한다. MASTER DOCX는 그대로 두고 역할 계약에 승인 프로필과 연결만 추가한다. 관찰 쪽·근거 PDF·현재 내용 해시·승인을 원고에 기록하고 실제 Word 재검을 마쳐야 한다. 승인 한도에서도 분량이 많으면 더 축소하지 않고 이어 배치한다. 아래와 참조의 임의 축소 금지에 대한 예외는 이 두 프로필의 명시된 범위뿐이다.

[실행용 MASTER](assets/latest-approved-reference.docx)와 [역할 계약](assets/layout-contract.json)을 사용한다. A01~A20 및 이번 변경은 [현재 변경 기준](references/current-revision.md)에 연결한다. 기존 A03 연속 배치는 위 새 쪽 규칙으로 대체했다. S/V 7.5pt·각주 8.5pt를 유지한다. 표지는 푸터와 같은 기존 책 아이콘·TOM’S EDU 로고를 크게 두고, `혼공교재 독해편` → 큰 과목명만 → 출판사·저자와 과 표시 → 기존 주제 박스·수량·학습 단계 순서로 구성한다. 별도 LESSON/SPECIAL LESSON 라벨·큰 과 번호는 출력하지 않는다. [최신 표지 기준](references/layout-rules.md#표지-개선-요청)을 따른다. 이번 승인에 한해 공통 MASTER의 표지 역할과 대응 계약을 갱신하며 다른 역할·로고 원본·썸네일·푸터는 보존한다. 구조 힌트의 영한 문법 대응 강조는 계약이 허용한 굵게·밑줄과 한국어 검정 파생 역할을 사용하며 MASTER는 바꾸지 않는다. 추가 역할도 계약을 사용하며 이후 교재 제작 중 기준 자산을 임의 수정하지 않는다.

공통 JSON을 `scripts/book_plan.py`로 컴파일한 계획으로만 학생용 DOCX를 생성한다. TXT·MASTER의 눈에 보이는 예시를 보고 모델별 조판 코드를 새로 만들거나 role/run을 임의 선택하지 않는다. 제작 진입점은 `scripts/build_book.py`이며 최초 create, 후속은 최신 파일 해시를 확인한 patch를 사용한다. 내부 master_docx가 변경/삽입 블록만 반영하고 check_saved_docx가 실제 저장본의 내용·역할별 서식·표·구역·푸터를 확인한다. 같은 파일명으로 전체를 재생성한 것을 부분 수정이라고 하지 않는다. Word에서 페이지 흐름을 별도로 확인한다. 태그 없는 기존 사용자 DOCX는 구조를 대조해 최소 수정하며 확인하지 않은 파일을 자동 통과시키지 않는다.

실행 가능한 도구와 정확한 입력은 runtime-and-data를 따른다. 기계 검사가 번역 정확성·문항 유일정답·독립 검수·조판 완료를 대신하지 않는다. 출력 역할이 없는 새 구성은 임의 디자인으로 만들어 놓고 동일 MASTER라고 보고하지 않는다.

새 원고의 기계 입력은 [공통 원고 데이터](references/manuscript-data.md)를 따른다. check_learning_content.py와 check_book.py로 자료 사이의 연결을 검사한 뒤 실제 저장 DOCX를 별도로 대조한다.

## 검수와 전달

전달용 교재 기본 이름은 `혼공독해교재_공통영어2_능률(민)_1과`처럼 `혼공독해교재_{과목}_{출판사(저자약칭)}_{과표시}`로 통일한다. 정규 과는 앞 0 없는 `N과`다. Further Reading 별도 교재는 `N과FurtherReading`을 허용한다. 표지 과 표시 뒤의 선택 괄호 문구는 [공통 원고의 cover.lesson_note](references/manuscript-data.md#표지-과-표시의-선택-괄호-문구)로 지정한다. Special Lesson과 약칭·기존 파일 처리·내부 관리 ID의 구별은 [파일명과 저장](references/workflow.md#파일명과-플랫폼별-저장)을 따른다.

‘최종 출고’ 요청은 **`{기본이름}_전체통합본.docx`와 분권 5개, 총 DOCX 6개를 담은 `{기본이름}.zip` 1개**를 제공하는 뜻이다. 분권 순서는 01 해석지, 02 지문분석지, 03 워크북+변형문제, 04 실전모의, 05 정답해설지다. 현재 확정 통합본에서 추출하고 [분권 제작·검수·파일명](references/split-delivery.md)을 필수 적용한다. 필요한 PDF는 내부 검수용으로 만들 수 있지만 ZIP에는 DOCX 6개만 넣는다. 스킬 수정 요청만으로 실제 교재를 출고하지 않는다.

최종 출고 완료와 ZIP 전달 뒤 남길 필수 파일·삭제 후보를 실제 목록으로 보여 주고 **“필수 파일만 남기고 나머지는 삭제할까요?”**라고 한 번 묻는다. 사용자 답을 기다리며 승인 전에는 삭제하지 않는다. [출고 후 정리 확인](references/split-delivery.md#출고-후-정리-확인)의 보존·승인 범위를 따른다.

검수 입력·반복 작업을 줄일 때는 [품질 유지형 검수 운영](references/review-efficiency.md)을 따른다. 기존 교육·조판 규칙과 S·L·M·N·J·K·R 및 문항 독립 2인 풀이는 유지한다. 새 기계 진단은 자동 내용 수정/승인이 아니며, 같은 현재 버전의 실제 분할 기록만 집계한다. 변경 전 합격 기록의 자동 상속은 지원하지 않는다.

제작·독립 검수·출고 단계를 구분한다. 문항은 독립 검수자 2명이 각각 풀이한다. 실제 독립 담당이 없으면 원고와 인계를 준비하고 미실시로 기록한다. 이 스킬을 읽었다는 이유만으로 새 대화방을 만들거나 다른 사람에게 메시지를 전송하지 않는다.

저장된 파일과 대응 FINAL을 대조하고, Word PDF의 페이지 경계·전체 축소본·수정 및 밀집 페이지를 확인한다. 접근할 수 없는 도구·폰트·Word 검수를 수행한 척하지 않는다. 임의 글꼴 대체 결과를 동일 조판으로 확정하지 않는다. 환경 부족이 있어도 가능한 내용·구조 작업을 수행하고 정확히 남은 검수를 인계한다.

현재 유효 요청·반영 상태·미해결 항목은 수정인계에, 상세 변경 이력은 별도 기록에 보존한다. 요청한 범위의 실제 파일과 검수 상태를 전달한다. 블로그·카페 게시, 설치·배포는 사용자가 요청한 범위에서만 실행한다.

워크북 조판의 최신 고정값: 오늘의 낱말·유의어·반의어 뜻 쓰기 영어는 10pt, 실전문제 뒤 새 쪽에서 4번 구문 결합 연습을 시작하고, 마지막 도움말 뒤 빈 줄 하나를 둔 다음 5번 핵심 문장 제목·전체 활동을 배치한다. 상세 범위와 옛 계속 표기 처리는 references/layout-rules.md를 따른다.
