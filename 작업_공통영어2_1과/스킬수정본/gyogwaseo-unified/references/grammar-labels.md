# 각주의 문법 라벨 제한

각주는 의미를 돕는 짧은 사전이다. 이 제한은 **혼공해석지 각주**에 적용한다. S/V 표시·구조 힌트·구문으로 해석하기의 형식을 대신 정하는 규칙으로 확대하지 않는다. 일반 구조 힌트는 필요한 구문과 연결 대상만 표시하고 무관한 주절·뒤 절과 그 해석은 제외한다. `analysis-content.md`에 따라 대괄호 대응을 유지한 `영어 → 한국어 해석 (structure_label)` 한 줄로 쓴다. 짧은 구조 이름표는 한국어 뒤에 한 번 붙인다. 짝 구조(`paired-structure`)는 선택한 원문 조각을 ` … `로 연결한 영어와 그 부분만 옮긴 한국어를 한 줄로 쓰며 구조 이름표나 설명문을 붙이지 않는다. 문법 형태·용법과 실제 문장 역할의 상세 판정은 내부 원고에 보존하며 학생용의 긴 설명문으로 출력하지 않는다. 수동·능동 완료의 기능 결합 힌트는 `category:function-combination`, `display_mode:verb-function`에 `lexical_step`을 연결하여 `produced(생산된) → is produced(생산된다) (be p.p.)`, `find(발견하다) → have found(발견했다) (have p.p.)`처럼 한 줄로 표시한다. 왼쪽 낱말 뜻과 오른쪽 실제 동사구 결합 뜻을 구별하며 수동 뜻을 두 번 더하지 않는다. 실제 시제·태·부정·양태와 표시 범위 안의 부사는 보존하고 주어·목적어·A/B 틀·by/for 구는 덧붙이지 않는다. 공식 `formula_label`과 낱말 뜻 괄호는 보통 글씨다. 일반 진행·완료진행 등 이번 p.p. 구별 밖의 기존 힌트와 `what to V + do → 무엇을 해야 할지`는 현행 형식을 유지한다. 별도 구조 이름표나 여러 단계의 풀이를 붙이지 않는다. 승인된 lexical_step의 기본 뜻→결합 뜻 한 줄만 허용한다. 모든 유형은 수동 줄바꿈 없이 작성하며 Word의 자연스러운 줄 감김은 허용한다.

## 뜻 뒤에 허용되는 짧은 병기

뜻을 먼저 제공한 뒤 필요한 경우 아래 병기를 덧붙일 수 있다.

- 관계대명사·관계부사
- 쉼표 뒤 계속적 which의 `(계속적 관계대명사)`
- 명사절 접속사·동격
- 분사구문
- 가주어 It과 실제 주어의 대응
- 능동 완료 낱말의 실제 p.p.형과 원형 관계: `(found는 find의 p.p.형)`

완성형 예시:

    who V′ — V′하는 (관계대명사)
    콤마+which V′ — 그리고 그것은 V′하다 (계속적 관계대명사)
    콤마+which S′ V′ — 그리고 그것을 S′(이/가) V′하다 (계속적 관계대명사)
    that S′ V′ — S′(이/가) V′하는 (관계대명사)
    where S′ V′ — S′(이/가) V′하는 (앞말을 꾸미는 관계부사)

전치사+관계대명사는 `by which S′ V′ — S′(이/가) V′하는 (관계대명사)`처럼 뜻을 통일한다. 실제 적용하면 뜻·시제·관계가 손상되는 예는 강제로 바꾸지 않고 reading_checks.review_record에 원문·문장/각주 ID·이유·문맥 뜻을 기록하여 1차 L 검수 때 사용자에게 보고한다. 일반 전치사·간접의문문·다른 관계사의 의미 규칙까지 확대하지 않는다. 자세한 적용은 gloss-rules.md를 따른다.
    that S′ V′ — S′(이/가) V′다는 (앞 명사의 내용을 설명)
    that S′ V′ — S′(이/가) V′라고 (접속사)
    V-ing — ~하면서 (분사구문) / give — 주다

라벨은 뜻이나 기능 설명을 대신하지 않는다. `who — (관계대명사)`처럼 뜻이 없는 항목은 금지한다. 선택적인 라벨 때문에 같은 표현을 별도 항목으로 다시 만들지 않는다.
쉼표 뒤 계속적 which의 각주 표제어는 쉼표 기호 대신 글자로 `콤마+which`라고 쓴다. which 자체가 주어이고 뒤에 동사가 오면 `콤마+which V′ — 그리고 그것은 V′하다 (계속적 관계대명사)`로 쓰며 S′를 덧붙이지 않는다. 뒤에 별도의 실제 주어와 동사가 오는 목적격 구조는 `콤마+which S′ V′ — 그리고 그것을 S′(이/가) V′하다 (계속적 관계대명사)`로 쓰고 S′를 보존한다. 사이에 부사가 있는지만으로 두 구조를 바꾸지 않는다. 이 표기 변경은 각주의 구조 표제어에만 적용하며 영어 원문·인용·문장 ID·offset의 실제 쉼표와 which는 그대로 둔다. ‘그리고/그런데’는 기존 문맥 기준에 따라 선택하되 주어인 which의 ‘그것은’과 목적어인 which의 ‘그것을’을 구별한다. 제한적 관계절·다른 관계사·전치사+which에 이 표기를 일괄 적용하지 않는다.
과거 관형 관계절은 실제 과거 연결을 보존해 `who V′ — V′했던 (관계대명사)`처럼 제공하고 힌트·연결 분석에도 `저질렀던`, `하고 싶어 했던` 등 맞는 관형 연결을 쓴다. 모든 관계절을 과거로 만들거나 계속적 which의 `그리고/그런데`를 `~했던`으로 바꾸지 않는다. 자연 해석은 문맥에 맞게 유지하며 연결 어미를 기계적으로 강제해 의미를 훼손하지 않는다.

문맥상 가주어 It+that 진주어로 확인한 구문은 전체 틀을 한 항목으로 제공한다. `It seems that S′ V′ — S′(이/가) V′하는 것 같다`, `It appears that S′ V′ — S′(이/가) V′하는 것으로 보인다`, `It is likely that S′ V′ — S′(이/가) V′할 가능성이 높다`는 예시다. 같은 위치의 It과 that을 따로 나누지 않는다. 실제 that절 내부의 필요한 낱말 뜻은 별도로 제공한다. to 진주어 등 다른 가주어는 실제 진주어 위치를 의미와 함께 짧게 안내하며, 실제 지시 it·강조구문과 구별한다. 연결 범위가 복잡하면 `analysis-content.md`의 구조 힌트 선정 기준을 적용한다.

## 기능 설명과 활용형 안내

수동·능동 완료는 기능 공식과 낱말을 나눈다. 수동의 낱말은 실제 p.p.형·수동 뜻(`be p.p. — ~되다 / produced — 생산된`), 능동 완료는 원형·기본 뜻과 실제 p.p. 관계(`have p.p. — ~했다 / find — 발견하다 (found는 find의 p.p.형)`)로 제공한다. 완료수동 `have been p.p.`는 수동이므로 실제 p.p.형을 유지한다. 전치사의 흔한 뜻으로 이해하기 어려운 `be provided with`·`be satisfied with` 등의 숙어는 한 각주로 유지한다. 독립 p.p.는 실제 형태·문맥 뜻(`held — 개최된`, `trained — 훈련받은`), 일반 정규과거 -ed는 원형·기본 뜻, 불규칙 과거는 현행 표기, 일반 -ing는 기존 기능/원형 분리를 유지한다. 이번 p.p. 구별 밖인 완료진행 `have been V-ing`와 오늘의 낱말 선정·표기는 별도 현행 규칙을 유지한다. 동사의 뜻을 완성하는 to V는 `decide to V — ~하기로 결심하다`, `struggle to V — ~하려고 애쓰다`처럼 동사 구문으로 묶고 V의 실제 낱말 뜻은 별도로 지원한다. 별도 목적이면 `use — 사용하다 / to V — ~하기 위해 / buy — 사다`로 나눈다. `had struggled to enter`는 `had p.p. — ~했다 / struggle to V — ~하려고 애쓰다 (struggled는 struggle의 p.p.형) / enter — 들어가다`다. 단독 to V에 `~하기로·~하려고·~하는 데`를 붙이지 않으며 문맥상 보충/목적이 불명확하면 실제 예와 추천안을 보고하고 답을 기다린다. `to V — ~하기 위해`, `V-ing — ~하는 것` 같은 남은 분리 대상의 기능 공식은 허용한다.

본문 용법의 구별이 먼저다. 정규과거 -ed 원형화, 수동/독립 p.p. 실제형, 능동 완료 p.p.의 원형+실제형 관계, 일반 -ing 기능 분리를 혼동하지 않는다. 완료수동은 have가 있어도 실제 p.p. 낱말을 유지한다.

- `fell — 빠졌다 (fall의 과거)`
- `written — 쓰인`, `be p.p. — ~되다 / produced — 생산된`, `test — 검증하다`(본문 tested가 일반 정규과거일 때)
- `better — 더 나은 (good의 비교급)`

원형 표제어 뒤에 자기참조 변화형 주석을 붙이지 않는다. 능동 완료의 `(found는 find의 p.p.형)`은 실제형과 원형의 관계 안내이므로 반드시 제공한다. 수동/독립 p.p.는 원형으로 바꾼 뒤 본문 표기를 부기하지 않고 실제 형태를 쓴다. 힌트·원문·S/V에는 실제 활용형을 보존한다. 필요한 의미 정보와 각주의 문맥 뜻을 분류 라벨로 대신하지 않는다.

후속 승인된 3인칭 단수 일반동사 각주는 원형 표제어를 쓰되 보통의 규칙형마다 ‘3인칭 단수형’ 라벨을 추가하지 않는다. 어휘적 has의 기존 불규칙형 안내가 있으면 `(has는 have의 3인칭 단수형)`처럼 실제형과 원형을 잇는다. 명사의 복수 s나 be·has·does 기능 공식은 이 표제어 규칙으로 바꾸지 않는다. 상세 범위는 `gloss-rules.md`의 실제 형태와 활용형을 따른다.

## 각주에 넣지 않을 분류 라벨

- 품사: 동사, 명사, 형용사, 부사, 전치사, 대명사
- 분사 분류: 동명사, 현재분사, 과거분사, 분사 후치수식
- 관계사 하위 분류: 주격, 목적격, 소유격, 계속적 용법. 단, 쉼표 뒤 계속적 which의 뜻 뒤에 붙이는 `(계속적 관계대명사)`는 위 승인 예외로 허용한다.
- 시제·태 분류: 현재완료, 현재완료 진행, 수동
- 문장 형식: 1형식부터 5형식
- 대상 설명 없는 가주어, 진주어, 가목적어
- 도치, 강조, 병렬, 등위접속
- 직접의문문, 간접의문문, 부정의문문
- 명사절, 주어절, 보어절, 시간절, 조건절, 양보절
- 원형 안내 없는 비교급, 최상급
- 축약, 삽입절, 인용, 반복 회피

이 목록은 의미 정보 대신 분류 이름을 붙이지 말라는 뜻이다. 위 ‘기능 설명과 활용형 안내’에 있는 원형·공식 안내와 충돌시키지 않는다.

명사절을 이끄는 that·whether에는 접속사 병기를 허용하지만 and·but·or나 부사절 접속사에 품사 라벨을 붙이지 않는다. and·but의 단독 각주는 제공하지 않는다.

## 표현 점검 예시

| 사용하지 않는 표기 | 의미를 지원하는 표기 |
|---|---|
| fuel (동사) — 부추기다 | fuel — 부추기다 |
| who (관계대명사·주격) — ~한 사람 | who V′ — V′하는 (관계대명사) |
| Switching (동명사 주어) — 바꾸는 것 | V-ing — ~하는 것 / switch — 바꾸다 |
| feeling (동명사·보어) — 느끼는 것 | V-ing — ~하는 것 / feel — 느끼다 |
| that (관계대명사·목적격) — ~한 | that S′ V′ — S′(이/가) V′하는 (관계대명사) |

라벨을 제거해도 문맥 뜻·기능 뜻·원형 관계는 남긴다. 항목 전체가 구조 설명뿐이면 각주에서 제거한다. 구조 힌트로 옮길지는 `analysis-content.md`의 구조 유형·필요성 기준으로 판단하며, 단순 문법 설명을 자동으로 옮기지 않는다. throw away·feed on 같은 숙어 뜻 자체는 힌트 후보가 아니며 실제 대상·동사·준동사의 연결 학습이 필요한 동사 구문만 후순위 후보로 둔다. 기능 공식과 낱말의 결합 해석은 후순위 힌트 후보로 제공할 수 있지만, 해당 용법의 각주를 생략하거나 공식 목록을 그대로 반복하지 않는다.
