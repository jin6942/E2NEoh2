# TOMSEDU 누적 조판 규칙

사용자가 2026-09-21에 요청한 지속 적용 지침. 새 디자인을 창작하지 않고 골든 마스터의 디자인을 복제·일반화한다. 최신 사용자 지시가 아래 기본값보다 우선한다.

## 2026-09-28 첫 단위 제목과 공통 안내 사이 빈 줄

첫 단위의 작성한 영어(한국어) 제목/주제 바로 뒤, ‘읽는 법’으로 시작하는 기호·S/V 공통 안내 바로 앞에 빈 문단을 정확히 하나 둔다. 문단 뒤 간격이나 수동 줄바꿈으로 대체하지 않는다. 전용 `interpretation_guide_gap`은 테두리 없는 기존 `analysis_sentence_gap`을 바탕으로 앞·뒤 간격 0, 고정 행간 11.8pt를 적용하고 다음 문단과 연결해 제목과 안내가 갈라지지 않게 한다. 다른 단위에는 추가하지 않는다. 기존 제목·안내 문구와 서식, 안내 뒤 구분선, 노란 도입 질문의 출력 제외, MASTER는 유지한다.

## 2026-09-26 해석지 헤더 통일과 도입 질문 제외

- 해석지 교재명은 정규화한 `metadata.course`와 `metadata.publisher_author`를 공백 하나로 연결하고 기존 과 표시를 붙인다. 예: `공통영어2 NE능률(민병천) · 4과 혼공해석지`. 자유 `metadata.book_name`이나 파일명의 밑줄을 헤더에 그대로 복사하지 않는다. 확인된 `능률(민병천)`·`NE능률(민병천)` 별칭은 중간 공백과 관계없이 `NE능률(민병천)`로 표시하되, 다른 출판사·저자를 임의 치환하지 않는다. 정규 과와 `Special Lesson 1`의 구별은 유지한다.
- 출처의 `본문`·`교과서 본문`은 학생 표시에서 `본문`으로 통일한다. 그 밖의 실제 출처명과 원문 소제목·원문·ID는 보존한다. 예: `문단 1 · 본문 · 문장 1~10`. DOCX와 FINAL 인계는 같은 표시 계산을 사용한다.
- **노란 도입 질문 ‘잠깐, 이 글은’은 모든 단위에서 출력하지 않는다.** 기존 `units[].hook` 값은 원고의 과거 자료로 보존할 수 있으나 DOCX·FINAL 인계 출력과 필수 검사에 사용하지 않는다. 없는 질문을 작성하거나 제거된 질문을 복원하지 않는다. A19의 질문 서식과 MASTER·계약의 `unit_hook` 역할은 과거 호환용으로 남아 있을 뿐 현재 출력 지시가 아니다.
- 헤더 순서는 교재명·과 표시 → 문단/출처/문장 범위 → 작성한 영어(한국어) 제목/주제 → 첫 단위에만 빈 문단 하나와 공통 안내 → 구분선이다. 읽는 법·기호·파란 ‘시작하기 전에 꼭’은 첫 단위에만 기존 공통 문구로 둔다. 위 2026-09-28 빈 문단 추가 이외의 기존 글꼴·크기·색·정렬·간격·안내 내용·MASTER·역할 계약은 바꾸지 않는다.

이 변경은 스킬의 표시 기준이다. 기존 원고·교재·출고 기록을 자동 수정하거나 새 검수·READY 판정을 부여하지 않는다.

## 2026-09-25 분석 설명·워크북 정답의 소폭 조판 조정 — 최신 승인

사용자는 실제 넘친 설명·정답을 한 페이지에 최대한 담도록 위아래 간격이나 글자 크기를 조금 줄이는 방식을 승인했다. 이 예외는 **Microsoft Word에서 넘침을 확인한 공통 단위의 분석 설명부 또는 워크북 정답**에만 적용한다. 분석은 `<unit_id>/analysis`의 마지막 `analysis_header` 뒤 설명부만 대상이며 앞의 영어·한국어 끊어읽기와 자연 해석은 보존한다. 정답은 `<unit_id>/answers`의 허용된 본문 역할을 대상으로 하고 표와 제목 글자 크기는 보존한다.

- 먼저 계약의 `compact_profiles.spacing`을 사용한다. 허용 역할의 문단 앞 간격은 0.5pt, 뒤 간격은 1pt 줄이되 0 아래로 내리지 않는다. 고정 행간은 0.8pt 줄이고, 대상 설명부의 8.5pt 빈 문단은 6.5pt로, 자동 1.15배 행간은 1.10배로 조정한다.
- 이것으로 부족할 때만 `compact_profiles.spacing_and_type`을 사용한다. 같은 간격 조정에 본문 글자 크기 0.5pt 감축을 더하되 최소 8.5pt를 유지한다. 제목과 유반의 글자 크기는 유지한다. 두 프로필은 승인 계약의 `role_map`에 있는 파생 역할로 적용하며 반복 감축·임의 수치·전역 축소로 확대하지 않는다.
- 기존 MASTER DOCX는 바꾸지 않는다. `layout-contract.json`에 승인된 두 프로필과 역할 연결만 추가하고, 대상 블록·현재 내용 해시·Word 관찰 쪽·근거 PDF 해시·사유·사용자 승인 근거를 `layout_adjustments`에 기록한다. [원고 필드 계약](manuscript-data.md#승인된-소폭-조판-조정)을 따른다.
- 혼공해석지, 각주·S/V·구조 힌트, 분석 끊어읽기 본문, 학생 필기 공간, 낱말 표의 10pt, 표지·용지 여백·푸터, 기존 실전문제·모의고사와 문항 사이 간격은 보존한다. 승인 범위 밖의 글자·행간·공간을 임의로 줄이지 않는 기존 규칙은 유지한다.
- 적용 뒤 실제 Word로 다시 렌더하여 넘침 해소와 가독성·잘림·고립·인접 페이지 흐름을 확인한다. 위 한도에서도 내용이 너무 많으면 더 줄이지 않고 의미 있는 묶음으로 이어 배치한다. 프로필 선택이나 구조검사 통과만으로 한 페이지 배치·조판 검수 완료를 선언하지 않는다.

## 실전 사용 후 추가 변경 — 2026-09-23

아래 변경은 이전 A03 및 옛 표지·정답 배치보다 우선하며, 실행 MASTER·계약·생성기·저장본 검사·시험본에 함께 반영한다. 기존 DOCX만 별도 교정하고 스킬 실행 경로를 옛 규칙으로 남기지 않는다.

- 분석지의 영어·한국어 끊어읽기·자연 해석이 끝나면 **다음 페이지**에서 내용 분석을 시작한다. 기존 `analysis_header`와 같은 파란 배경1F4E79·흰색 굵게10.5pt의 큰 헤더를 먼저 넣고, 그 아래 `▶ 글의 의도`→흐름→쉬운 풀이→어법→유반을 배치한다. 글의 의도와 끊어읽기 해석을 같은 페이지에 두지 않는다. 별도 모범 해석 자료를 부활시키는 변경은 아니다.
- 미니 모의고사 문항 사이에는 기존 빈 줄 두 개에 해당하는24.7pt 여유를 둔다. `mock_question_prompt_spaced`의 문단 앞494twips로 구현하고, 첫 문항 및 명시적 새 페이지의 첫 문항에는 기본 prompt 역할을 쓴다. 빈 문단을 페이지 맨 위로 밀어 올려 공백을 만들지 않는다. 약2문항/쪽은 가독성 목표이며 강제 수용량이 아니다. 긴 문항은1문항/쪽도 허용하고 글자·행간을 줄여 맞추지 않는다. 워크북 문제 뒤 핵심 문장 앞 간격을 ‘문항 사이’로 오인해 함께 늘리지 않는다.
- 표지 상단은 아래 최신 표지 개선 요청에 따라 기존 로고·교재 이름·과목명·출판사와 과 표시로 구성하며, 과거 LESSON 라벨·큰 과 번호 배치는 사용하지 않는다. 영어II의 표시명은 영어2로 통일한다. 남색 상자 영어 제목은22pt 굵게 흰색 **한 문단**, 최소28.6pt 행간·뒤10pt로 만들고 임의 줄바꿈을 넣지 않는다. 한국어 제목10.5pt, 상자 폭523.3pt·좌우16pt·상하14pt를 유지한다. 원문의 제목을 줄이거나 작은 글씨로 자동 축소하지 않으며 실제로 한 줄에 들어가지 않는 제목은 Word 검수에서 발견·보고한다.
- 표지 수량·학습 단계 안내는 실제 원고에서 계산한 기존 고정 문구로 통일한다. 이름·학습일 문단은 생성하지 않는다. 마지막 학습 단계 뒤 연결을 종료한다.
- 워크북 정답의 ‘오늘의 낱말’과 ‘유의어·반의어 뜻 쓰기’는 테두리 없는 고정3열 표에1·2·3 /4·5·6 순서로 배치한다. 기존 `workbook_word_answer`의 번호·뜻 run서식과 내용은 보존한다. 총폭10466twips, 열3489/3489/3488twips, 오른쪽 셀 여유120twips, 상하·왼쪽0, 행 분할 금지, 제목과 첫 행 연결을 적용한다. 마지막 행의 남는 칸은 비워 둔다. 다른 해설 문단을3열로 만들지 않는다.
- 문맥 어휘 문제의 다섯 대상 단어와 밑줄 의미 문제의 발문 속 대상 표현에 실제 밑줄 서식을 적용한다. 원숫자나 주변 문구까지 일괄 밑줄 처리하지 않는다. 역할계획 `required_underlines`는 전체 표시문자열의 코드포인트 범위이며 저장본의 실제 유효 밑줄 서식으로 재확인한다. 밑줄 의미 발문의 글꼴·파란색·굵기는 기존 발문 역할을 유지한다.

이전 A01~A20은 이 절과 충돌하지 않는 범위에서 유지한다. 표지 영어 제목은 `cover_topic_box`에 영어·한국어 두 항목만 전달한다. 옛 세 문단 입력은 오류로 처리한다. 어휘 답안표는 `workbook_answer_grid` 역할에 기존 정답 run목록을 항목별로 전달한다.

## 실제 교재 대조 후 확정한 A01~A20 — 2026-09-23

2026-09-25 도구 보완: 혼공해석지·분석 본문의 `★핵심`은 한 덩어리로 유지한다. `fixed_labels.key_marker` 내부에 Word 호환 폭 없는 줄바꿈 방지 문자 U+FEFF를 넣으며 보이는 문구·공백 폭·색·크기·MASTER run은 유지한다. 계약의 이 고정 표식만 두 출력이 공통으로 사용한다. 이 별표 보완 자체는 다른 표식을 바꾸지 않는다.

3과 Cowork #15 후속 승인: 분석 본문의 `★핵심`은 문장 끝 위치를 유지하고 마지막 영어 낱말과 함께 줄이 바뀌게 한다. 생성기는 표식 앞 기존 공백 3개를 같은 수의 U+00A0으로 출력하며 표식 내부 U+FEFF·주황색·글꼴·크기는 그대로 둔다. 번호 옆으로 옮기거나 보이는 간격을 없애지 않는다. 해석지의 기존 출력, 원문·청크, MASTER·역할 계약은 바꾸지 않는다. 실제 Word에서 마지막 낱말과 표식이 함께 이동하는지 확인한다.

S-7 후속 승인: 문제 번호 `①②③④⑤`는 관리 문단의 해당 글자만 `맑은 고딕`으로 고정한다. `circled_number_typography` 계약에 따라 ASCII·hAnsi·eastAsia·cs 모두 지정하고 글꼴 테마의 대체 지정을 남기지 않는다. 원문자와 본문을 별도 run으로 나누되 번호의 색·굵기·크기·밑줄과 기존 공백/NBSP, 영어·한국어 본문 서식은 그대로다. 학생용 영어 선택지 전체를 파랑·굵게 바꾸는 지시가 아니다. ⑥ 이후 번호·다른 기호·썸네일·MASTER DOCX는 이 예외에 포함하지 않는다. 실제 Word에서 번호가 다른 글꼴로 대체되지 않았는지 확인한다.

## 페이지 나눔과 검수

검수 입력 배분은 [품질 유지형 검수 운영](review-efficiency.md)을 따른다. J/K는 약 10쪽씩 실제 흐름에 맞춰 나누되 전체 페이지와 모든 인접 페이지 연결을 확인한다. 작은 각주·밀집/수정 페이지는 판독 가능한 해상도로 보고 이미지 배율 상한을 두지 않는다. Word 렌더는 두 번으로 제한하지 않으며 결함이나 재수정이 있으면 필요한 검수를 추가한다. 글꼴·공간·쪽 나눔 등 기존 조판 기준은 바꾸지 않는다.

- 제목만 페이지 하단에 남기지 않는다. keep-with-next를 소제목과 다음 본문에 적용한다.
- 영문 문장→주어·동사→각주→힌트→나의 해석→답안 공간을 가능한 한 묶는다. keep-together와 keep-with-next를 역할에 맞게 사용하고, 문장 블록 사이에서 나눈다. 전체 문단·전체 교재를 하나의 연결 체인으로 묶지 않는다.
- 표 행이 잘리거나 답안선만 다음 장에 남지 않게 한다. 한 블록이 한 페이지보다 길면 의미 있는 경계에서 나누고 계속 표기를 쓴다.
- 다른 과에 4과의 강제 페이지 나눔 위치, 10개 문단, 60문장, 32문항, 95쪽을 하드코딩하지 않는다.
- DOCX를 PDF로 렌더하고 전체 페이지 축소본 및 수정한 페이지·밀집 페이지의 원본 크기 이미지를 확인한다. 겹침, 글자 잘림, 로고·푸터 침범, 빈 페이지, 제목·답안선 고립을 확인한다.
- 확정 원고와 DOCX/PDF 텍스트를 대조해 문장·문제·정답 누락을 확인한다. 조판 검수를 내용 정확성 검수와 혼동해 보고하지 않는다.
- 기존 파일을 보존하고 요청한 DOCX를 전달한다. ‘최종 출고’는 [전체통합본+분권 5개](split-delivery.md)의 DOCX 6개를 ZIP 1개에 담아 제공하며 비교·검수용 PDF는 내부에 둔다. 분권의 바뀐 쪽 흐름도 실제 Word에서 확인한다. 반영한 규칙과 페이지 수 변화를 짧게 보고한다.

## 단위 끝 복습란과 제외한 응원 문구

## 구조 힌트의 영어·한국어 한 줄 대응

2026-09-24 최신 승인: structure_hint의 7.5pt·문단 간격·영어 기존 색·한국어 검정(000000)을 유지하고 양쪽 모두 보통 글씨를 기본으로 한다. `emphasis_links`로 같은 문법 기능과 선정 공식 S′/A의 주어 조사 이/가를 연결한다. 일반 문법은 양쪽 굵게+한 줄 밑줄을 적용하고 명시적 `ko-only-verb-construction` 동사 결합은 영어 보통·한국어 조사/연결 어미만 강조(돕다·제공하다 같은 동사 낱말 뜻 전체 제외)를 적용한다. 영어·한국어 대괄호 전체를 굵게 하던 규칙과 한국어 조사만 독립적으로 강조하던 규칙을 대체한다. 직역을 우선하며 강조가 대괄호·무관한 조사·내용어까지 번지지 않게 한다. 일반형은 필요한 구문과 연결 대상만 `영어 → 한국어 해석 (짧은 구조 이름표)`로 한 줄에 쓴다. 무관한 주절·뒤 절과 그 해석은 표시하지 않는다. ‘구조 힌트’와 끝의 이름표는 각각 한 번만 표시한다. 짝 구조(`paired-structure`)는 선택한 원문 조각을 ` … `로 연결한 영어와 그 부분의 한국어 뜻을 한 줄로 표시하며 이름표·설명문·문장 전체 해석을 붙이지 않는다. 예: `both to hide … and to secretly crawl up to … → 숨기 위해서도 … 몰래 기어서 다가가기 위해서도 …`. 수동·능동 완료의 기능 결합 힌트는 `category:function-combination`, `display_mode:verb-function`에 `lexical_step`을 연결하여 `produced(생산된) → is produced(생산된다) (be p.p.)`, `find(발견하다) → have found(발견했다) (have p.p.)`처럼 한 줄로 표시한다. 왼쪽 낱말 뜻과 오른쪽 실제 동사구 결합 뜻을 구별하며 수동 뜻을 두 번 더하지 않는다. 실제 시제·태·부정·양태와 표시 범위 안의 부사는 보존하고 주어·목적어·A/B 틀·by/for 구는 덧붙이지 않는다. 공식 `formula_label`과 낱말 뜻 괄호는 보통 글씨다. 일반 진행·완료진행 등 이번 p.p. 구별 밖의 기존 힌트와 `what to V + do → 무엇을 해야 할지`는 현행 형식을 유지한다. 기능 결합 display_pairs는 정확히 한 쌍이며, 승인된 lexical_step은 같은 줄의 접두 낱말 뜻이지 추가 대응 쌍이 아니다. 모든 유형은 수동 줄바꿈을 넣지 않고 Word의 자연스러운 줄 감김은 허용한다. 글씨나 나의 해석 필기 공간을 줄여 억지로 한 물리적 줄에 맞추지 않는다. 내부 문법 설명은 출력하지 않는다. 이번 대응 강조 변경은 MASTER를 보존하고 structure_hint 내부의 밑줄 허용과 기존 한국어 검정 파생 역할을 사용한다. 다른 역할의 색·굵기·밑줄은 바꾸지 않는다. 강조 위치는 원고에서 문법 대응을 직접 검토해 명시하고, 잘못된 의역을 교정하면 양쪽 위치를 다시 맞춘다. 생략 관계사는 `display_mode:omitted-relative`로 `[(that) …]`처럼 힌트에만 보충한다. 괄호는 보통 글씨로 두고 안의 관계사 글자와 한국어의 최소 대응 부분에만 굵게+한 줄 밑줄을 적용한다. 원문·청크·S/V·각주·정식 해석은 바꾸지 않는다. 생략 명사절 접속사 that은 관계사와 구별해 `display_mode:omitted-conjunction`, `omitted_conjunction:that`을 사용한다. 힌트에만 `[(that) laws had to be changed] → [법이 바뀌어야 한다고] (명사절 접속사 that 생략)`처럼 표시하고, 괄호는 보통·that 글자와 실제 S′의 이/가 및 연결 어미는 굵게+밑줄로 대응한다. 생략 관계사는 기존 `omitted-relative`를 유지한다. 두 유형 모두 빈 대응 링크로 대체하지 않고 원문·청크·S/V·각주·자연 해석에 보충 표지를 추가하지 않는다. 생략된 주어·to까지 이 예외를 확대하지 않는다. 승인 표지·시제태 공식·lexical_step 뜻 괄호 외에 강조용 따옴표·괄호·별표·설명문이나 원문에 없는 말을 임의로 추가하지 않는다. 생략 주어·to 등 승인 범위 밖이며 실제 대응이 없는 요소의 빈 링크는 내부 사유를 명시한다.
