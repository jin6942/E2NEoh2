# 최종 출고: 전체통합본과 분권 5개

사용자가 ‘최종 출고’, ‘최종 출고해’처럼 완성 교재 출고를 요청하면 기본 전달물은 **전체통합본+분권 5개, DOCX 6개를 담은 ZIP 1개**다. 내용 제작·수정 단계는 기존 공통 원고와 누적 통합 DOCX 한 벌에서 계속하고, 출고할 때 같은 확정본에서 분권을 만든다. 스킬 규칙 수정 요청만으로 기존 교재를 출고하거나 재생성하지 않는다.

## 고정 구성과 이름

`{기본이름}`은 workflow의 `혼공독해교재_{과목}_{출판사(저자약칭)}_{과표시}`다. 예: `혼공독해교재_공통영어2_능률(민)_1과`.

전달 ZIP 이름은 `{기본이름}.zip`이다. 아래 DOCX 6개를 ZIP 최상위에 담고 폴더·PDF·검수 보고서·원고·이전본은 넣지 않는다.

| 전달 파일 | 포함 범위 |
|---|---|
| `{기본이름}_전체통합본.docx` | 표지부터 정답·해설까지 현재 확정된 전체 내용 |
| `{기본이름}_01_해석지.docx` | 기존 표지·공통 안내와 모든 학습 단위의 혼공해석지 |
| `{기본이름}_02_지문분석지.docx` | 모든 단위의 영어·한국어 끊어읽기·자연 해석과 분석 설명부·구문으로 해석하기·유반 |
| `{기본이름}_03_워크북+변형문제.docx` | 모든 단위의 워크북과 그 안의 실전/변형문제·구문 연습·핵심 문장 해석 활동 |
| `{기본이름}_04_실전모의.docx` | 기존 미니 모의고사 전 회차의 문제·공유 장문·선지 |
| `{기본이름}_05_정답해설지.docx` | 빠른 정답, 모든 워크북 활동의 답, 변형/실전문제 및 모의고사 정답·해설 |

‘실전모의’·‘워크북+변형문제’는 전달 파일의 분권 이름이며 본문의 기존 고정 제목·문항 수·편성을 바꾸거나 새 문제를 추가하라는 지시가 아니다. 표지는 기존 전체 표지를 01권에 한 번 보존하며 다른 권은 기존 영역 제목으로 시작한다. 별도 다섯 표지나 새 광고 문구를 임의 제작하지 않는다. 전체통합본 파일명에 ‘전체통합완성본’·‘최종’·날짜·버전을 덧붙이지 않는다.

## 같은 확정본에서 추출

`scripts/split_book.py`에 현재 전체 역할 계획과 그 계획에 대응하는 최신 누적 DOCX를 넣는다. 원문·교재 내용을 다시 쓰거나 TXT에서 재조판하지 않는다. 관리 블록 ID로 각 영역을 배정하고 원래 단위·문장·문항·답 순서를 유지한다. 전체통합본 사본은 입력 DOCX와 바이트가 같아야 한다.

```text
python scripts/split_book.py export "최신통합원본.docx" "역할계획.json" "출고분권" --base "혼공독해교재_공통영어2_능률(민)_1과"
python scripts/split_book.py verify "출고분권/분권내보내기.json"
```

위 입력명·과목·과는 현재 교재의 실제 값으로 바꾼다. `--base`에는 `_전체통합본`·권 번호·확장자를 넣지 않는다. 내보내기는 여섯 DOCX와 이들을 묶은 ZIP, 내부 `분권내보내기.json`을 만들며 기존 출력 파일을 덮어쓰지 않는다. 다음 출고는 새 작업 하위 폴더에서 검증하고 최종 제공 링크를 갱신한다. 내부 목록은 범위·해시 대조 자료이며 ZIP에 넣지 않는다.

다섯 분권을 합쳤을 때 통합본의 모든 본문 블록이 정확히 한 번씩 있어야 한다. 원래 표지·공통 안내는 위 배정대로 보존한다. 관리되지 않은 본문, 불명확한 구분, 알 수 없는 블록, 누락·중복은 임의 분류하지 않고 원인을 확인한다. 학생용 01~04권에 05권의 답안 블록이 들어가면 안 된다. 표·각주·구조 힌트·강조·글꼴·여백·머리말/꼬리말·관계·미디어를 보존한다. 새 문서로 인해 달라지는 실제 쪽 흐름은 분권별로 확인한다.

분권을 독립 수작업 원본으로 만들지 않는다. 수정 요청은 공통 원고·통합 DOCX에 반영하고, 대응 FINAL과 영향을 받은 분권을 다시 연결한다. 이전 검수 대상과 다른 파일을 이름만 같게 덮어쓰지 않는다. 안전한 새 출력 폴더에서 여섯 파일·목록·해시를 확인한 뒤 실제 전달 경로를 확정한다.

## 검수와 전달

**PDF는 필요한 내부 검수에 생성해도 되지만 기본 전달물에는 포함하지 않는다.** 사용자의 최신 정정은 PDF 생성 금지가 아니라 PDF 전달 제외다. Word 렌더·S/L/M/N/J/K/R·문항 2인 블라인드 풀이·사용자 추가 요청 확인은 유지한다. 구조 검사만으로 시각 검수나 출고 완료를 선언하지 않는다.

통합본의 내용·원문·FINAL·정답·기존 검수 연결을 확인하고, 다섯 분권의 범위·저장본·분권별 Word 쪽 흐름도 검수한다. 통합본에서 정상인 페이지가 분권에서도 정상이라고 가정하지 않는다. 새 권의 첫/마지막 페이지, 표·필기선, 제목과 다음 본문, 문항과 선지, 각주·푸터·큰 빈 페이지를 확인한다. 분권 때문에 내용이 바뀌지 않았다면 S/L/M/N 의미 검수를 무조건 처음부터 반복하지 않고, 기존 현재 버전의 근거와 추출 보존 대조를 연결한다. 변경된 내용이나 미해결 결함은 기존 재검 원칙대로 처리한다.

`scripts/verify_split_release.py`로 통합본의 필수 출고 증거와 현재 분권 목록·실제 파일·분권 Word/시각 검수·출고 대조를 확인한다. 기존 `verify_release.py`의 통합본 통과나 `split_book.py`의 추출 성공만으로 여섯 파일 출고가 완료되었다고 보고하지 않는다. 실제 기록 형식은 [출고 기록](release-record.md)의 분권 절을 따른다.

압축 후 ZIP을 다시 열어 엔트리가 정확히 여섯 DOCX인지, 이름·바이트가 실제 검수한 파일과 같은지 확인한다. 누락·중복·다른 버전·PDF나 내부 자료 혼입·압축 손상은 출고 오류다. 내부 목록의 `delivery_zip`에 실제 ZIP 경로·이름·해시를 연결한다.

완료 응답에는 **검수한 DOCX 6개가 든 ZIP 1개의 실제 다운로드 링크**를 제공한다. 여섯 개의 개별 링크나 폴더 링크만으로 대신하지 않는다. PDF·검사용 이미지·내부 원고·검수 JSON을 ZIP 또는 기본 다운로드 목록에 넣지 않는다. 검수 미실시 또는 필요한 분권이 빠졌으면 최종 출고 완료라고 하지 말고 정확한 미완료 항목을 보고한다.

## 출고 후 정리 확인

최종 출고 검증이 완료되고 실제 ZIP 다운로드 링크를 제공한 뒤 현재 교재 작업 폴더를 확인한다. 남길 필수 파일과 삭제 후보의 실제 파일명·경로를 간결하게 구분해 보여 주고, 다음 문구로 한 번 묻는다.

**필수 파일만 남기고 나머지는 삭제할까요?**

선택지를 표시할 수 있으면 ‘예, 표시한 후보만 삭제’와 ‘아니요, 그대로 보관’을 제공한다. 질문 뒤 사용자 답을 기다리고 스스로 답을 선택하거나 응답 부재·시간 경과를 승인으로 간주하지 않는다. 이 스킬 수정 요청은 앞으로 정리 질문을 하라는 지시이며 현재 파일 삭제 승인이 아니다. 정리 여부의 답을 받지 못해도 이미 완료된 출고를 취소하거나 미완료로 되돌리지는 않는다.

필수 보존 대상은 최신 전달 ZIP, 그 ZIP에 든 DOCX 6개, 제작 기준 원문·공통 원고·현재 FINAL, 사용자 요청·수정이력과 현재 출고 기록이다. 현재 분권 목록·출고 기록·검수 증거가 직접 또는 간접 참조하는 파일도 보존한다. 내부 PDF·Word 실행 기록·시각 검수 근거는 사용자에게 전달하지 않는다는 이유만으로 삭제 후보에 넣지 않는다. 재개·검수 추적에 필요한 스킬·MASTER·설정도 정리 대상에서 제외한다.

현재 출고 검사 결과의 `protected_paths`와 출고 기록·검증 결과 파일 자체를 보존 목록에 포함한다. 내용이 같아도 `source_docx`와 전달용 `integrated_docx`는 각각 연결된 필수 경로이므로 중복 사본으로 삭제하지 않는다. 연결된 파일은 이름 변경·이동으로도 참조를 끊지 않는다. 출고 상태가 바뀌면 옛 보호 목록만 믿지 말고 현재 기록을 다시 확인한다.

삭제 후보는 현재 출고·재개 기록에 쓰이지 않는 것으로 확인한 임시 파일·중간 산출물·불필요한 중복 사본으로 한정한다. 오래된 이름이나 확장자만으로 판단하지 않으며 다른 과·공유 원문·상위 폴더까지 범위를 넓히지 않는다. 후보가 없으면 없다고 표시한다.

사용자가 승인하면 표시한 후보만 삭제한다. 실행 직전 실제 경로가 해당 작업 폴더 안인지, 최신 출고·제작 파일의 참조 대상이 아닌지 다시 확인한다. 목록 밖 파일을 추가로 삭제하려면 바뀐 목록을 다시 제시한다. 삭제 후 필수 파일과 ZIP이 그대로 있는지 확인하고 처리한 목록을 수정인계에 남긴다. 거절하면 그대로 보관하며 같은 출고에서 반복해서 묻지 않는다.
